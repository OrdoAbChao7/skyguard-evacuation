# 核心研究贡献（V6）

> 本文只陈述**已实现且可复现**的贡献；理论依据与证据分离，未实机验证的部分明确标注。

## 贡献一：信息价值驱动的主动调查（VoI）

**问题**：信息不完整时，固定巡查既浪费资源又可能漏掉高风险区域。

**方法**：
- 贝叶斯后验 + 信息熵 + 预期风险损失降低 − 时间/资源/失败成本；
- 动作覆盖范围（目标/邻居/全部）与调查预算；
- 序贯重试：最大次数、冷却、指数退避、证据冲突折扣；
- 停止条件：VoI 阈值、预算耗尽、无可用动作、转人工。

**证据**：
- 5 种子 × 200 次 × 4 策略：VoI 成本 1.77 min vs 固定 3.57 min；风险降低 0.0486 vs 0.0572（多区域/成本权衡）。
- 权重敏感性：信息增益/成本参数 ±50% 会改变 10–25% 的推荐动作。
- 失败条件：突增/强不确定场景下 VoI 可能退化为调查不足；参数必须现场标定。

**实现**：`voi.ts`、`multi-voi.ts`、`investigation-session.ts`、`agent.ts`。

## 贡献二：多区域风险传播与联合调查

**问题**：单区域调查忽略相邻区域的风险传导与“一次动作覆盖多区域”的共享价值。

**方法**：
- 区域—通道—出口图，边权 = 容量因子 × 距离因子；
- 风险传播 `propagated = local + damping × Σ neighborRisk × edgeWeight`；
- 调查优先级 = 传播风险 × 不确定性 × 中心性；
- 联合 VoI：覆盖权重（目标 1 / 邻居 0.5 / 全局 0.3），成本只计一次。

**证据**（300 次合成风险配置）：
- V6.2 30 种子（目标轮换）：总风险降低 0.2154 vs 0.0472（约 4.6×，配对 d_z=2.06），覆盖 6.74 vs 1.59 区域；
- 成本 0.584 vs 0.253（约 2.3×），效率差 +0.0917（95% CI [0.0755,0.1079]）；
- **设计敏感性**：V6.1 同目标策略下效率差不显著，V6.2 轮换目标后为正；必须并列报告，不能无条件宣称效率更优。
- 适用条件：风险传播强、预算充足；预算紧张时单区域更划算。

**实现**：`risk-graph.ts`、`multi-voi.ts`、`/api/v1/mvp/multi-region`、大屏“多区域协同调查”面板。

## 贡献三：可信安全约束与人机闭环

**问题**：Agent 若直接规划/发布/派发，会把模型错误放大为现场风险。

**方法**：
- Agent 只调用工具、只创建待审批工单；
- 独立 Validator（15 类硬约束）+ 四态状态机；
- 工单上下文版本、过期失效、管理员重新确认、幂等键；
- 工作人员接单/执行/反馈写回观测，触发重新评估。

**证据**：
- 故障注入 5/5 检出；状态机 6/6；错误发布 0；
- 业务闭环 20/20，状态流转 20/20；
- 审批后观测变化会阻断派发（回归测试）。

**实现**：`validator.ts`、`state-machine.ts`、`ops.ts`、审批/反馈 API 与前端。

## V6.1 审计更正（2026-11-05）

1. **多区域 VoI**：V6 的 0.083 vs 0.024 未做预算配对；同预算/同证据的 V6.1 结果为
   0.189 vs 0.030（成本 0.57 vs 0.074，效率差 95% CI 含 0）。结论改为：
   **总风险收益显著更高，单位成本效率无显著差异**。
2. **序贯重试**：V6 的 91% vs 68.6% 是 2 次 vs 1 次尝试；同为 2 次尝试预算时，
   重试与不重试的成功率/检测/决策均相同（92%/76.5%/96.5%）。**重试不提高有限尝试预算下的成功率**。
3. **预测**：严格滚动下自适应在 stable/decline/missing 更好，surge/periodic persistence 略优；
   区间覆盖率未稳定达到 90/95%。不得笼统宣称某一模型全面更优。
4. **风险图**：damping/覆盖权重会改变排序与推荐；仍是未标定的运维启发式，不是真实迁移概率。
5. **感知**：匹配算法改为最大基数二分匹配；仍无数据集/权重/真实精度。

## 贡献五（V6.5）：资源生命周期与单实例可信状态

**问题**：Agent 推荐与人工审批之间如果只做“状态字符串”，会出现人员重复占用、
预算在最后一个候选动作越界、审批后资源已被他人占走、重启后旧授权复活等问题。

**方法**：
- 工单创建即建立资源预留（人员、预算单位、人员分钟、TTL、场景版本）；
- 审批确认、拒绝/取消/过期/失败释放、完成结算；
- 幂等键绑定规范化请求指纹；并发创建同一人员只允许一个成功；
- `MVP_STATE_FILE` 统一快照：安全观测/事件/方案 + 工单/预留/预算 + Agent 运行 + 审计；
  临时文件 + fsync + backup + 原子改名 + SHA-256 + revision；损坏时 fail closed；
- 工单完成与现场反馈在同一事务范围提交。

**证据**：
- `reservations.test.ts` 8 组：创建/预检、拒绝/取消/失败/完成、预算边界、幂等冲突、
  并发人员、过期重确认、场景版本失效；
- `state-persistence.test.ts`：跨业务恢复、主文件损坏回退 backup、temp 恢复、
  revision 冲突、未来 schema 拒绝启动；
- 实机进程重启：工单/预留/人员状态从 `revision=2` 快照恢复；双副本损坏时 exit 1。

**边界**：单实例；跨工单/预算/事件的共同事务由单快照近似，不是分布式事务；
预算结算使用声明值而不是现场实际耗时。

## 贡献六（V6.5）：公平实验与预测不确定性传播

**方法**：
- 公平 VoI：所有策略对同一物理动作获得相同覆盖，观测从似然采样；
- 预测实验：6 种合成机制 × 30 种子 × 严格滚动起点；5 基线 + 自适应；
- 区间覆盖率/宽度、失效检测、敏感性、消融、失败案例；
- 预测可靠性 `failed` 时 VoI 预测动作不可用。

**证据**：
- 公平 VoI（`evaluation/voi-v2/`）：多区域总风险降低仍更高（0.1711 vs 0.0446），
  但 V6.2 的 d_z=2.06 被信息权限差异放大为公平条件 d_z=1.27；效率低于随机/启发式。
- 预测（`evaluation/v65/`）：自适应配对平均优于全部基线（-2.4 至 -9.2 绝对误差），
  但不是任何单一机制最佳；surge 95% 覆盖率 0.738，明显低于名义值；
  periodic/noisy 的预测动作几乎总被可靠性门槛阻断。

**边界**：合成机制；区间是残差分位近似；真实场馆仍需标定与现场数据。
