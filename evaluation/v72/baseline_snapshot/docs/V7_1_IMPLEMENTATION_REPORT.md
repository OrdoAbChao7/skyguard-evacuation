# SkyGuard V7.1 实施报告

> 日期：2026-11-09。范围：滚动重规划机理、预测区间突破、事件触发/路线稳定性、Shadow Mode 工程准备、红队与数据核验。
> 最终证据：`evaluation/v71/v71-final-20261109T211702/`。
> 全部为合成/模拟数据；不代表真实场馆效果。

## 1. 执行摘要

V7.1 已完成当前环境可独立完成的研发：

1. **滚动重规划机理实验（A-G + H/I）**：30 种子 × 5 场景 × 9 策略；
2. **预测区间突破**：ACI、变点检测、偏差校正 conformal、可靠性门控；30 种子 × 7 机制；
3. **规划升级**：事件触发、legacy/V7 求解器切换、路线稳定性选项、求解延迟统计；
4. **Shadow Mode**：Feature Flag、统一快照、双方案独立校验、超时/异常回退、审计、旧链路可恢复；
5. **红队与数据核验**：出口/通道故障、NaN/异常预测输入、过期观测、Shadow 回退、公开数据集许可；
6. **文档与证据链**：实施/实验/审计报告、状态、主张、限制、数据集候选。

**核心结论（必须与负向结果一起引用）**

- 性能提升主要来自**滚动重规划**：B vs A 未疏散 −682.8 [−715.8, −649.9]，完成时间 −5.11 [−5.29, −4.94]。
- V7 时间扩展 MPC 进一步降低完成时间到 8.81（legacy 周期重规划 13.88），但路线切换人数显著更高（4390 vs 754）。
- 事件触发对 **legacy** 规划器减少约 35% 重规划次数（求解 −0.28ms/场景），且不损失完成率；对 **V7 MPC** 却变差（完成时间 10.29 vs 8.81）。
- 预测与队列反馈相对仅重规划**没有显著增量收益**（完成时间差约 −0.03/+0.03，CI 跨零）。
- ACI + 变点检测把 surge 95% 覆盖从 0.748 提升到 0.846、regime_shift 后段从 0.809 提升到 0.907，但 periodic 覆盖从 0.982 降到 0.833，整体覆盖差为 0（CI 跨零），门控失败率上升；这是**混合结果**。
- Shadow Mode 只记录、不发布；默认关闭；V7 不得替换默认安全链路。

## 2. 预测系统突破

### 2.1 实现

| 组件 | 内容 |
| --- | --- |
| `conformal.ts` | Adaptive Conformal Inference（ACI）、偏差校正区间（中位数 + 绝对残差分位）、在线变点检测（CUSUM/Page-Hinkley + 单点异常）、有限步变点膨胀、可靠性门控 |
| `forecast-advanced.ts` | V7.0 集成（Kalman/ARIMA/Holt-Winters/在线 LSTM/regime）保持不变；V7.1 在其点预测上替换区间机制 |
| 测试 | ACI 加宽/收窄、校准不足回退、变点检测、膨胀、偏差校正、门控失败、异常输入 |

### 2.2 协议

- 30 固定种子 × 7 机制；点预测与 V7.0 完全相同，只改变区间；
- 在线因果：第 t 步区间只使用 t 之前的残差与覆盖结果；
- 对照：`v70_static`（V7.0 区间）、`aci`（ACI + 偏差校正）、`aci_cp`（再加变点膨胀）；
- 指标：90/95 覆盖、宽度、校准率、门控失败率、变点触发率；Holm 校正。

### 2.3 结果（最终运行）

| 机制 | v70 95% 覆盖 | aci 95% 覆盖 | aci_cp 95% 覆盖 | aci_cp 宽度 | aci_cp 门控失败率 |
| --- | --- | --- | --- | --- | --- |
| stable | 0.9333 | 0.9247 | 0.9280 | 60.30 | 0.3237 |
| surge | **0.7484** | 0.8140 | **0.8462** | 442.58 | 0.8914 |
| decline | 0.9828 | 0.9624 | 0.9613 | 63.32 | 0.3129 |
| periodic | 0.9817 | 0.8333 | 0.8333 | 368.57 | 1.0000 |
| missing | 0.9321 | 0.9208 | 0.9186 | 73.16 | 0.5769 |
| noisy | 0.9333 | 0.9290 | 0.9269 | 419.49 | 1.0000 |
| regime_shift | 0.8086 | 0.6527 | **0.9065** | 556.32 | 0.8591 |

- 整体配对（aci_cp − static）：95% 覆盖差 **0.0000 [−0.0119, 0.0119]**（Holm 不显著）；
  宽度 +7.43 [2.73, 12.13]（显著），门控失败率 +0.2278 [0.1984, 0.2571]（显著）。
- 结论：改善最困难机制（surge/regime_shift）的尾部覆盖，但牺牲 periodic 覆盖与宽度，并触发更保守的门控；
  **不是全局改进**，不得只引用 surge/regime_shift。
- 门控失败时预测不得进入 VoI/规划；安全四态仍由观测可信度决定。

## 3. 滚动重规划机理（A-G + H/I）

### 3.1 策略

| 代号 | 策略 | 求解器 | 重规划 | 预测 | 队列反馈 |
| --- | --- | --- | --- | --- | --- |
| A | static_mcf | legacy | 一次 | 否 | 否 |
| B | periodic_reactive | legacy | 每 2 分钟 | 否 | 否 |
| C | event_triggered | legacy | 事件/队列/偏差 | 否 | 否 |
| D | mpc_no_forecast | V7 | 每 2 分钟 | 否 | 否 |
| E | mpc_forecast | V7 | 每 2 分钟 | 是 | 否 |
| F | mpc_queue | V7 | 每 2 分钟 | 否 | 是 |
| G | full | V7 | 每 2 分钟 | 是 | 是 |
| H | full_stable | V7 | 每 2 分钟 | 是 | 是 + 路线稳定 |
| I | event_full | V7 | 事件触发 | 是 | 是 |

场景：baseline_surge、exit_failure、corridor_closure、bidirectional_stress、multi_zone_surge；
所有策略共享实际入流、执行模型与预算；30 种子。

| B periodic legacy | 0 | 13.88 | 43383 | 754 | 7.33 | 1.28 |
| C event legacy | 0 | 13.75 | 42641 | 763 | 4.75 | 1.00 |
| D MPC no forecast | 0 | 8.81 | 14373 | 4390 | 5.03 | 1.80 |
| E MPC forecast | 0 | 8.77 | 14291 | 4731 | 5.05 | 1.89 |
| F MPC queue | 0 | 8.83 | 14401 | 4410 | 5.05 | 1.76 |
| G full | 0 | 8.81 | 14322 | 4745 | 5.06 | 1.81 |

| I event_full | 0 | 10.29 | 23123 | 4701 | 5.00 | 1.78 |

### 3.3 机理回答

- **是否主要来自滚动重规划？** 是。B vs A：未疏散 −682.8，完成时间 −5.11；V7 MPC 进一步把完成时间降到 8.81。
- **预测是否提供额外信息价值？** 否（本模型）：G vs F 完成时间 −0.027 [−0.068, 0.015]；E vs D 见配对表；未疏散均为 0。
- **队列反馈是否有用？** 否（本模型）：G vs E 完成时间 +0.033 [−0.001, 0.068]，CI 跨零；出口队列/服务衰减没有改变排序。
- **MPC 是否有不必要计算成本？** 事件触发对 legacy 重规划 −35%、求解 −0.28ms/场景；V7 每次求解更昂贵（+0.52ms vs legacy），但换来完成时间大幅下降；是否值得取决于任务时限与切换成本。
- **复杂算法何时不如简单基线？** I（事件+V7）完成时间 10.29、队列 23123，明显差于 G（8.81/14322）；H（路线稳定）切换更多且求解更慢。复杂不等于更好。
- **场景差异**：exit_failure 下所有重规划策略仍完成疏散，但 V7 完成时间 10.47 vs legacy 15.17；multi_zone_surge 下 V7 8.73 vs legacy 14.0。

### 3.4 路线切换

- V7 MPC 的切换人数约为 legacy 的 5.8 倍（4390 vs 754），这是时间扩展重分配的自然代价；
- H 的“保持上一出口”启发式没有降低切换（4960），并增加求解成本（3.13ms）；**保留为负结果**；
- I 的事件触发也没有降低切换（4701），并显著恶化完成时间；**保留为负结果**；
- 后续需要状态增广网络或显式切换代价的 MILP 才能系统优化切换。

## 4. Shadow Mode（可选 V7 Planner Adapter）

### 4.1 设计

- Feature Flag：`V7_SHADOW_MODE=1` 才启用；默认关闭；
- 输入快照：场景/约束/观测版本、需求、可用通道/出口、SHA-256；
- 双方案：legacy 规划器结果 + V7 时间扩展求解器结果；
- 独立校验：两套方案都经 `validateSafetyPlan` 复算；
- 执行投影：两套方案都经同一拥堵执行模型评估 makespan/队列；
- 回退：V7 超时（`V7_SHADOW_MAX_SOLVE_MS`）、异常、校验失败、无解时只记录回退原因；
- 发布：**Shadow 永不发布 V7 方案**；legacy 方案与四态完全不受影响；
- 审计：`plan.shadow_compare` trace stage；
- 只读 API：`GET /api/v1/safety/v70/shadow`。

### 4.2 启用条件（未满足前不得启用）

1. Shadow 运行 ≥ 30 天/≥ 1000 次重规划，V7 校验失败率为 0 或可解释；
2. V7 在完成时间/队列/未疏散上稳定不劣于 legacy（Holm 校正）；
3. 切换成本、人工审批与回滚演练完成；
4. 独立安全评审签署；
5. 先从“建议”模式开始，不直接替换默认路径。

### 4.3 当前状态

- Shadow 默认关闭；测试覆盖开启、关闭、预算为零回退、reset 清空、API 只读；
- 未做真实场馆验证；未启用。

## 5. 红队与修复

| 级别 | 问题 | 处置 |
| --- | --- | --- |
| P0 | 事件触发被“执行导致的人数下降”误触发，退化为周期策略 | 改为只对未预期人数上升、入流、队列、最长间隔触发 |
| P0 | 空窗口强制重规划导致事件策略多算 | 仅当活动计划无后续路线时强制重规划 |
| P1 | 预测对称/纯符号区间在 surge 下覆盖不足 | 偏差校正 + 绝对残差分位；保留 ACI 单独失败的负结果 |
| P1 | 路线稳定启发式未降低切换、增加计算 | 保留为负结果，不宣称有效 |
| P1 | Shadow 超时是事后检查而非抢占 | 文档明确；预算为零立即回退；后续可用 worker 实现真抢占 |
| P2 | Shadow 记录仅内存，重启丢失 | 已记录；不影响安全发布；后续可纳入统一状态 |
