## 1. 执行摘要

V7.2 完成当前环境可独立执行的研发与验证：

1. **Track A（最高优先级）**：实现迟滞、切换惩罚、承诺窗口、自适应混合四类稳定性机制；
   修正时间扩展求解器的双向通道共享容量模型；运行 30 种子 × 6 场景 × 6 策略公平对照。
2. **Track B**：可复用的场馆标定档案、校验、参数估计、相机/观测适配器与版本追踪；
   合成档案不能冒充实测/标定值。
3. **Track C**：Shadow 回放压力与故障注入（求解器异常、校验失败、预算为零、过期观测、快照篡改），
   证明同一输入快照、双方案独立校验、V7 永不发布、确定性回放。
4. **华为生态**：AgentArts 真实平台未配置时明确标注，本地官方契约 stub 验证会话头/SSE/工具决策；
   新增 ONNX 参考模型导出与 CPU 推理基准，并给出 ATC 转换模板；**无 NPU 实机证据**。
5. **红队**：修复双向通道超容量、承诺候选容量冲突、预测非有限值污染、相机离线/未来时间戳等可复现缺陷，
   全部补回归测试。

**核心结论（必须与代价一起引用）**

- 标准 MPC 切换人数 5261.8；迟滞降到 4268.3（−18.9%），切换惩罚/承诺降到 3334.3（−36.6%）；
  完成时间分别增加 0.05 / 0.45–0.51 分钟，队列人·分钟增加约 1.3k–2.7k，最大密度增加约 0.07–0.08。
- 这些差异在 Holm 校正后显著；**稳定性不是免费的**，且密度上升意味着需要人工/安全阈值审查。
- 承诺式求解是逐区域贪心多商品近似；容量冲突时降低承诺份额，仍冲突则显式报告并由调用方拒绝。
- Shadow 240 次回放确定性 0 不一致；快照完整性不一致只出现在人为篡改用例（40/40 被标记）。
- 没有真实平台/硬件结果；ONNX CPU 基准 p50≈0.015ms 只证明导出链路，不是 NPU 性能。

## 2. Track A：路线稳定性与安全 MPC

### 2.1 问题

V7.1 显示 V7 MPC 完成时间显著优于 legacy，但切换人数约为 legacy 的 5.8 倍。
切换意味着现场反复改道、广播/引导成本与人群困惑，是必须显式建模的运行代价。

### 2.2 实现

| 组件 | 文件 | 内容 |
| --- | --- | --- |
| 稳定性策略 | `backend/src/services/safety/planning/route-stability.ts` | 模式解析/夹紧、支配出口、切换影响、承诺决策、容量复核 |
| 承诺式求解 | `backend/src/services/safety/planning/stable-solver.ts` | 逐区域顺序求解 + 已用容量预留 + 份额回退 + 容量冲突报告 |
| MPC 集成 | `backend/src/services/safety/planning/mpc-planner.ts` | `stability` 选项、运行中故障注入、紧急覆盖、密度/风险追踪 |
| 求解器 | `backend/src/services/safety/planning/strategies.ts` | 双向通道共享容量迭代、已用容量扣除、方向键容量覆盖 |

四种稳定性机制：

1. **迟滞（hysteresis）**：承诺方案的目标劣化在容差内才采用；
2. **切换惩罚（switch_penalty）**：比较「目标 + 惩罚 × 切换人数」；
3. **承诺窗口（commitment）**：计划发布后 N 分钟内保持上一出口集合；
4. **自适应混合（adaptive）**：窗口内/拥堵时承诺，否则切换惩罚。

安全硬条件（任一不满足即回退无承诺方案）：

- 承诺方案未疏散人数不得高于无承诺方案；
- 合并方案逐分钟走廊/出口容量不得超限（`capacity_violations` 必须为空）；
- 目标劣化不得超过 `maxObjectiveDegradation`（默认 0.3）；
- 出口不可用（事件封锁/运行中故障）时承诺立即失效，并记录紧急覆盖。

**承诺份额**：默认 80% 当前在场人数固定到上一出口，其余与未来到达仍参与自由优化。
若容量冲突，份额自动降至 60%/40%/20%；仍冲突则返回带 `capacity_violations` 的方案，调用方必须拒绝。

**紧急覆盖**：`midRunDisruptions` 在指定分钟封锁出口/通道，重算有效网络；
故障后的执行路线不得再使用故障出口/通道（回归测试覆盖）。

### 2.3 双向通道容量修正（红队发现）

时间扩展求解器原先给双向通道两个方向各全额容量，而执行模型与独立校验器按同一走廊每分钟总容量计算。
这会让计划在物理上超容量（例：C_MID 双向合计 220 > 180）。
修正：求解器先按方向全额求解，若某分钟双向合计（含已承诺流量）超物理容量，按需求比例分配并重解（最多 8 轮）；
稳定求解器显式传递「已用容量」，核心按 `名义容量 − 已用` 建弧。
该修正使 V7.1 的绝对数字发生变化（更保守），V7.1 冻结证据仍是历史运行，不回写。

### 2.4 结果（30 种子 × 6 场景，180 组合）

| 策略 | 未疏散 | 完成时间 | 队列人·分钟 | 最大密度 | 切换人数 | 求解(ms) |
| --- | --- | --- | --- | --- | --- | --- |
| A legacy_static | 784.9 | 19.00 | 57772.6 | 1.963 | 0 | 0.6 |
| B mpc_standard | 0 | 9.89 | 19481.7 | 2.696 | 5261.8 | 19.2 |
| C mpc_hysteresis | 0 | 9.94 | 20824.1 | 2.769 | 4268.3 | 39.7 |
| D mpc_switch_penalty | 0 | 10.34 | 22103.1 | 2.776 | 3334.3 | 40.3 |
| E mpc_commitment | 0 | 10.41 | 22209.2 | 2.776 | 3334.7 | 40.3 |
| F mpc_adaptive | 0 | 10.41 | 22209.2 | 2.776 | 3334.7 | 40.0 |

> 求解耗时为单机测量，存在 ±1–2ms 波动；切换/完成时间/队列为确定性仿真指标。

- C vs B：切换 −993.5 [−1227.4, −759.7]，完成时间 +0.05 [0.0005, 0.0995]；
- D vs B：切换 −1927.6 [−2193.0, −1662.1]，完成时间 +0.45 [0.353, 0.547]；
- E/F vs B：切换 −1927.1 [−2192.1, −1662.1]，完成时间 +0.51 [0.413, 0.609]；
- 所有 MPC 策略未疏散均为 0；稳定性求解耗时约为标准 MPC 的 2 倍（约 38–40ms/场景）。

**负向/混合结果**：

- 密度与队列上升：稳定性把流量留在原出口，拥堵在区域侧累积；
- 迟滞只降低约 19% 切换，代价最小；惩罚/承诺降低约 37%，代价更大；
- 承诺与惩罚在多数场景结果相同（惩罚阈值 10 使承诺方案在惩罚后目标上胜出），
  说明机制差异被当前参数掩盖，不能宣称两者独立有效；
- 高需求/容量紧张时承诺候选因未疏散增加或容量冲突被拒绝，收益消失（保留在 rows）。

### 2.5 运行中故障

`midrun_exit_failure` 场景（第 4 分钟北出口故障）：

- legacy 静态方案平均 1.13 条路线在故障后仍使用故障出口（无重规划，安全风险）；
- 所有 MPC 策略故障后使用故障出口路线为 0；
- 承诺/自适应策略记录紧急覆盖（平均 1 次/场景），承诺立即失效；
- 未疏散保持 0。

## 3. Track B：场馆标定流水线

### 3.1 能力

| 能力 | 实现 |
| --- | --- |
| 场馆几何/区域/出口/通道导入 | `VenueProfileSchema`（Zod）与场景 ID 关联 |
| 容量与通行参数配置 | 每个参数带 `value/unit/provenance/source/method/measured_at/samples/CI` |
| 相机到区域映射 | `cameras[]`（ROI、标定状态/版本、传感器元数据） |
| 参数估计 | 出口服务率、步行速度；n≥10 且 CV≤0.3 才允许 calibrated |
| 场景配置校验 | `validateVenueProfile`：引用完整性、ROI、正数、来源一致性 |
| 观测适配器 | 相机计数 → DensityObservation；拒绝离线/过期/未来时间戳/低置信度 |
| 数据来源分级 | `synthetic/public_dataset/authorized_real/mixed` |
| 版本追踪 | 应用档案返回新场景版本 `+profile.<id>.<version>` 与逐项变更清单 |

### 3.2 关键约束

- 合成档案中出现 `measured/calibrated` 直接判为错误（`synthetic_claims_measured`）；
- `calibrated` 必须有 ≥5 样本与置信区间；
- `unknown` 参数不会被应用（`blocked`），不会静默填充；
- 应用标定返回新对象，不修改输入场景；变更清单记录 before/after/provenance/source。

### 3.3 证据

`evaluation/v72/<run>/calibration_*.json|md`：

- 合成档案校验通过（0 错误/0 警告）；
- 合成样本估计被降级为 `estimated`（步行速度 1.172 m/s）；
- 观测适配器 fresh 接受、stale/低置信度拒绝；
- 场景未被原地修改。

## 4. Track C：Shadow Mode 验证

### 4.1 增强

- `ShadowSolver` 注入接口（仅用于故障注入/回放，不改变生产发布语义）；
- `integrity`：legacy/V7 计划声明人数必须与快照需求一致；
- 不一致时 `legacy_snapshot_mismatch` / `v7_snapshot_mismatch`，决策强制 `legacy_only`；
- 快照哈希覆盖版本、需求、可用走廊/出口。

| budget_zero | 1.0 | 0 | 40 `solve_budget_zero` |
