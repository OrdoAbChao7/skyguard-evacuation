# AGENTS.md — SkyGuard 独立项目开发准则

本仓库是从灵小禅仓库拆出的**独立安全决策项目**。任何 Agent 修改代码、场景或文档前，
必须先读本文件与 [`docs/LIMITATIONS.md`](docs/LIMITATIONS.md)。

## 1. 不可触碰的边界

1. **场景是数据，判定是代码**：区域 / 通道 / 出口 / 演示脚本 / 地图层只能通过
   `data/scenarios/*.json` 修改；不得把具体场景写死进 TS/TSX。
2. **规划器不得自我认证**：`validator.ts` 必须独立重建约束，不读 `plan.status`
   或规划器的中间成功标志。任何"让校验器复用规划结果"的改动都必须拒绝。
3. **未知一律不可用**：`status: unknown` 与 `capacity_per_min: null` 必须继续被排除在规划之外，
   并在被使用时由校验器报硬违规。
4. **状态优先级固定**：`DEGRADED > REJECT > REROUTE > NORMAL`。数据不可信时不得下
   "方案不可行"的结论。
5. **不得伪造数据**：场景中的面积、容量、置信度、provenance 必须如实标注；
   性能数字只能来自 `npm run bench` 的本机实测，并保留原始 JSON。

## 2. 换场景的流程

见 [`docs/SCENARIO.md`](docs/SCENARIO.md)。核心原则：新增 JSON + 可选底图，
不改疏散引擎；新场景必须通过结构校验、`npm test` 与 `npm run demo`。

## 3. 验证要求

修改安全域代码后必须运行：

```powershell
npm test          # 后端 42 用例 + 前端 4 用例
npm run demo      # A/B/C 演示场景最终状态必须与 expected_state 一致
npm run build     # backend tsc + frontend vite build
```

涉及规划 / 校验性能时额外运行 `npm run bench`，并提交重新生成的
`evaluation/performance.json`。

## 4. 对外表述

- 只能说"研究原型 / 辅助决策"，不能说"应急指挥系统"或"已通过安全认证"；
- 未在真实昇腾设备上跑过的推理，不得表述为"已完成昇腾适配"；
- 合成场景数据不得表述为真实场馆测绘结果；
- 不得引用灵小禅仓库的历史竞赛成绩作为本仓库成果。

## 5. SkyGuard MVP 增量约定（2026-11-05）

本仓库在安全内核之上新增 MVP 业务闭环（体育场散场）。修改相关代码时必须遵守：

1. **Agent 不得越权**：Agent 只能创建 `PENDING_APPROVAL` 工单；审批、派发必须由
   `admin` / `safety_operator` 完成；接单、执行、反馈必须由被指派的 `staff` 完成。
2. **VoI 参数只能来自场景文件**：先验、似然、损失、成本、权重不得由大模型生成，
   也不得在代码里写死；修改必须同步 `docs/VOI_MODEL.md` 与实验。
3. **AgentArts 不得伪装**：没有真实租户与实机调用时，界面必须显示 `LOCAL DEMO` /
   `AGENTARTS UNAVAILABLE`；不得声称已完成平台集成。
4. **MCP 工具与本地 Agent 共用一份实现**（`services/mvp/tools.ts`），
   新增工具必须声明角色、Schema、超时并写入审计。
5. **前端不得写死演示结果**：预测、Agent、人员、工单、审批状态全部来自后端 API。
6. **不允许删除或弱化原安全测试**；MVP 改动后至少运行：
   `npm test`、`npm run demo`、`npm run demo:mvp`、`npm run build`，
   实验相关改动还要运行 `npm run experiments:mvp` 并提交新报告。
7. **模拟与真实严格区分**：人员位置、无人机、概率参数、实验数据均为合成；
   没有真实硬件与凭证时，只能完成适配器、契约测试和接入文档。

6. 安全加固默认项：限流、请求 ID、生产错误脱敏；CORS/CSP/读鉴权按环境配置。
7. 不把 `stale` 工单、未校验方案、DEGRADED 数据展示为可用/已验证。

# 7. 项目长期目标与研发战略

## 7.1 North Star

将 SkyGuard 建设为面向大型公共活动的主动感知与可信协同决策研究系统。

最终形成完整链路：

```text
多源人群感知 → 多区域态势理解 → 短时人流预测 → VoI 主动调查
→ 风险关联分析 → 容量约束疏散规划 → 独立安全校验 → 人工审批
→ 现场执行反馈 → 持续重新评估
```

最终目标是形成具有科研创新、华为技术应用、真实场景验证、可复现实验和优秀工程实现的
高水平竞赛作品，冲击华为 ICT 创新赛全国一等奖。

**不得将竞赛目标理解为允许夸大实验结果或降低安全标准。**

## 7.2 三条核心研究主线

**第一：主动感知与信息价值决策。**
- VoI 驱动的调查动作选择；
- 不确定性建模与贝叶斯证据更新；
- 调查预算约束；
- 多区域联合信息价值；
- 多传感器信息互补；
- 调查停止与人工升级条件。

**第二：多区域风险协同决策。**
- 区域—通道—出口图模型；
- 人流变化与瓶颈风险分析；
- 多区域预测；
- 动态资源分配；
- 多目标疏散规划；
- 全局风险与局部效率权衡。

**第三：可信 Agent 与安全人机协同。**
- AgentArts 工作流编排；
- MCP 工具生态；
- 昇腾 CANN/MindSpore 边缘推理；
- 独立安全校验器；
- 四态安全状态机；
- 审批、工单、执行与反馈闭环；
- 全链路 Trace 和审计。

三条主线必须形成统一系统，不能发展成互相无关的功能集合。

## 7.3 华为技术长期路线

优先研究并逐步验证：

1. **AgentArts**：真实工作流编排、工具调用和 Trace。
2. **MCP**：标准化工具接入和权限控制。
3. **Ascend**：模型转换、CANN 部署、OM 推理。
4. **MindSpore**：模型训练、优化和部署适配。
5. **Edge-Cloud**：云端复杂分析与边缘实时感知协同。

必须区分**架构设计、接口适配、模拟验证和实机验证**四种状态，不得混写。

## 7.4 真实场景验证路线

从公开数据集开始，逐步推进：

- 人群计数公开基准；
- 真实视频标注评测；
- 摄像机标定；
- 场馆区域测绘；
- 通道与出口容量测量；
- 人员资源参数标定；
- 受控场景演练；
- 专业安全评审。

没有实际证据，不得升级验证等级。

## 7.5 长期研发优先级

所有 AI Agent 必须按照以下优先级决策：

- **P0**：安全正确性、数据真实性、可复现性。
- **P1**：核心算法有效性和真实技术验证。
- **P2**：系统可靠性、工程部署、交互体验。
- **P3**：展示效果、附加功能和非核心优化。

禁止为了 UI 炫酷、代码规模或模型复杂度牺牲前三项。

## 7.6 AI Agent 长期工作原则

每次接手项目必须：

1. 读取 `AGENTS.md`；
2. 读取 `docs/PROJECT_STATUS.md`；
3. 读取 `docs/LIMITATIONS.md`；
4. 读取 `research/CLAIMS.md`；
5. 检查 Git 状态和历史变更；
6. 明确当前任务对长期目标的贡献；
7. 先检查已有实现，避免重复造轮子；
8. 先提出最小可行修改，再逐步验证；
9. 保留历史实验和负面结果；
10. 更新状态文档和研究主张。

每次完成重要里程碑，都必须更新 `docs/PROJECT_STATUS.md`。

## 7.7 永久禁止事项

- 不得伪造 AgentArts、昇腾或无人机实机结果。
- 不得将合成数据描述为真实测量数据。
- 不得将通过测试描述为通过安全认证。
- 不得让大模型直接绕过独立 Validator。
- 不得让 Agent 自行审批或派发任务。
- 不得为了获得漂亮实验数字而删除失败样本。
- 未经用户许可不得破坏 Git 历史或提交、推送。

# 8. V6.5 资源、持久化与感知边界（2026-11-09）

1. **资源预留是安全语义，不是 UI 状态**：工单创建即预留人员/预算；审批确认、拒绝/取消/
   过期/失败释放；完成才结算预算。不得在未预留或预留过期时派发。
2. **幂等键绑定请求指纹**：同键同参返回同一工单；同键异参必须报冲突，禁止静默复用。
3. **统一状态文件**：配置 `MVP_STATE_FILE` 时，安全观测/事件/方案、工单/预留/预算、
   Agent 运行与审计内存视图必须一次原子提交；损坏或版本超前时拒绝启动，禁止清空后继续。
   单实例限制不得被表述为多实例一致性。
4. **AgentArts 只做本地准备**：官方契约、重试、SSE、越权拒绝、续接测试可完成；
   无真实租户时不得把 stub 结果写成平台实机成功。
5. **预测可靠性**：区间过宽/数据不足的预测不得作为 VoI 证据；预测不得替代四态安全判定。
6. **感知密度门禁**：人数只有在 surveyed 标定、与场景区域一致面积、足够置信度同时满足时
   才能生成可信观测；CityStreet/P2PNet 等外部数据不得伪造密度或报告精度。
7. **验证门槛**：涉及安全域/工单/状态/预测/感知的修改至少运行 `npm test`、`npm run build`、
   `npm run demo`、`npm run demo:mvp`；预测修改另跑 `npm run benchmark:v65 --prefix backend`。

# 9. V7.0 研究理念与阶段约定（2026-11-09）

```text
人潮未至，先察其势；
险境将生，先问其因。
千路交汇，求其有序；
万流奔涌，守其有度。
```

这四句是 SkyGuard 的长期技术理念，约束所有 V7 及后续研发：

1. **预测先于响应**：提前识别人群变化与潜在风险；
2. **感知先于决策**：通过主动调查降低环境不确定性；
3. **优化服务于安全**：动态规划不能突破安全约束；
4. **智能必须受到约束**：Agent 可以分析和建议，但必须经过独立验证与人工授权。

## 9.1 V7 阶段目标

| 阶段 | 研究内容 | 必须留下的证据 |
| --- | --- | --- |
| V7.1 | 预测方法对照（persistence/EMA/Kalman/ARIMA/Holt-Winters/在线 LSTM/状态感知集成）、regime、conformal 区间、漂移检测；时间扩展流、最大流、受限 MILP、滚动时域 MPC | `evaluation/v70/<run>/prediction_*`、`planning_*`、30 种子、配对统计、消融与失败案例 |
| V7.2 | 联合 VoI（区域相关性、冗余、预算、顺序）、动态拥堵与风险传播（人员守恒、队列、容量、出口服务率） | `joint_voi_*`、公平动作覆盖与观测采样、Oracle 上界、敏感性 |
| V7.3 | 预测/联合感知/动态规划/拥堵反馈统一集成；Validator 独立复算；过期观测、伪造、并发、幂等、重试 | API 预览、回归测试、安全审计与红队报告 |

## 9.2 V7 新增硬性规则

1. **预测只使用过去数据**：滚动起点不得使用目标点或未来数据选择方法/校准区间；
2. **区间必须报告经验覆盖率**：覆盖率低于名义值时不得用于安全告警阈值；
3. **公平对照**：联合 VoI 的所有策略必须共享同一动作覆盖、观测采样与预算；不得通过改变信息权限制造优势；
4. **同一执行模型**：动态规划比较必须在同一拥堵/队列执行模型下进行；不得通过改变统计口径制造“零拥堵”；
5. **负结果保留**：预测、联合 VoI、MPC 的负向或混合结果必须写入 README、summary 与原始 rows；
6. **预测不得绕过校验**：带预测到达的 MPC 步骤是条件投影，不得声明“已通过独立校验”；只有对应当前观测的步骤可以做独立校验；
7. **参数来源**：相关性、冗余、BPR、服务衰减等参数必须来自场景文件或显式标注为未标定启发式；
8. **不调参制造胜利**：不得根据测试结果反复调参直到显著；消融与敏感性必须与主结果一并报告。

# 10. V7.1 研究验证与主链路接入约定（2026-11-09）

## 10.1 研究结论必须先于工程启用

1. 滚动重规划是 V7.1 的主要收益来源；预测/队列反馈在当前模型中**没有显著增量**，不得作为启用 V7 的理由；
2. 事件触发只对 legacy 规划器显示算力收益；对 V7 MPC 变差，不得默认开启；
3. ACI+变点检测改善 surge/regime_shift 覆盖，但降低 periodic 覆盖并提高门控失败率，必须作为混合结果报告；
4. 路线稳定启发式未降低切换，保留为负结果；
5. 任何新算法必须同时报告有利与不利指标、失败案例与消融。

## 10.2 Shadow Mode 硬性规则

1. `V7_SHADOW_MODE` 默认关闭；关闭时 recompute 行为必须与 V6.5 完全一致；
2. Shadow 只记录比较，**永不发布** V7 方案、不审批、不改变四态；
3. 两套方案必须经独立 Validator；V7 超时/异常/校验失败必须自动回退；
4. 输入快照必须包含场景/约束/观测版本、需求、可用网络与 SHA-256；
5. 只有满足 `docs/V7_SHADOW_MODE.md` 验收清单，才允许提出启用建议；
6. 不得把 `v7_eligible_for_review` 表述为安全批准。

## 10.3 数据与预测

1. 公开数据集使用前必须核验许可、划分与引用；仓库代码许可不等于数据许可；
2. 静态图片计数精度不得表述为动态疏散预测精度；
3. 预测可靠性失败时不得进入 VoI/规划；安全四态仍由观测可信度决定；
4. 不得把合成入流/预测误差模型表述为真实数据。

# 11. V7.2 路线稳定性、标定与可信集成约定（2026-11-10）

## 11.1 稳定性机制硬性规则

1. 迟滞/切换惩罚/承诺/自适应必须同时报告**切换下降**与**完成时间、队列、最大密度、求解延迟**；
   只引用切换下降视为选择性报告；
2. 承诺候选必须满足：未疏散不增加、逐分钟走廊/出口容量不超限、目标劣化在护栏内；
   任一不满足必须回退无承诺方案；
3. 承诺式逐区域求解是贪心近似，不得表述为联合最优；
4. 出口不可用（事件/运行中故障）时承诺必须立即失效，并记录紧急覆盖；
5. 惩罚/承诺/迟滞参数（10/人、0.05、6 分钟、80%）必须标注为未标定实验值。

## 11.2 容量模型规则

1. 双向通道的物理容量由两个方向共享；求解器、执行模型与独立校验器必须口径一致；
2. 不得恢复「两个方向各得全额容量」的旧实现；
3. 承诺/预留容量必须以「已用容量」显式传递，不得用方向残量之和代替物理容量；
4. 最终方案必须逐分钟容量复核；冲突必须显式报告，不得静默采用。

## 11.3 场馆标定规则

1. 每个参数必须带 `provenance/source/method`；`measured/calibrated` 还需时间与样本；
2. **合成档案不得包含 measured/calibrated**；统计稳定不能把合成数据升格为 calibrated；
3. `unknown` 参数不得应用；标定应用必须返回新场景版本与逐项变更清单；
4. 真实标定需要测绘、摄像机内外参、现场样本、授权与隐私合规；
5. 不得把合成标定表述为真实场馆参数。

## 11.4 Shadow 与华为生态规则

1. Shadow 默认关闭、只记录、不发布；快照人数不一致必须标记并禁止 eligible；
2. 求解器注入仅用于故障注入/回放，不得改变生产发布语义；
3. AgentArts 无真实租户/凭证时只能写 `not_configured` 与本地契约 stub，不得声称已接入；
4. Ascend 无 `npu-smi/atc/CANN` 时不得声称 NPU/OM 结果；ONNX CPU 基准必须标注 `CPUExecutionProvider`；
5. 新证据必须写入 `evaluation/v72/<run-id>/` 并更新根 `MANIFEST.json`；负向结果不得删除。
