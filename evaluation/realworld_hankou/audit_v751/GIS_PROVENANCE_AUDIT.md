## 0. 证据等级定义

| 等级 | 含义 |
| :---: | :--- |
| **A** | 官方测绘/竣工资料直接给出，含文号、图号、控制点或可核验原始文件 |
| **B** | OSM 原始数据（含下载时间、端点、原始文件、SHA-256、ODbL 归属） |
| **C** | 人工从公开地图/资料数字化，未保留原始底图与控制点 |
| **D** | 权威文献/国家标准的通用参数 |
| **E** | 工程假设/经验取值，无现场标定 |
| **F** | 仅用于测试的虚拟数据 |

> 关键原则：**坐标投影变换正确，不等于源数据几何精度正确。** 本次独立复算证明的是 EPSG:4326→EPSG:4547 的数学实现正确；它不能证明 11 个闸门坐标本身达到 0.1 m 或任何亚米级精度。

## 2. 11 个闸门锚点与投影复算

### 2.1 硬编码锚点

`scripts/gis/generate-hankou-scenario.ts:132-260` 直接硬编码 11 个 `HANKOU_GATES`，包括经纬度、净宽、高程、通行方式。代码中**没有**读取任何 OSM 文件、GeoJSON、Shapefile、控制点文件或水务局图纸。

11 个闸门净宽合计 **100.5 m**；核心三门 G01+G02+G03 = **21.5 m**。仓库中不存在“54 m 总出口宽度”的字段、常量或求和结果。

### 2.2 独立投影复算

使用独立实现的 **Krüger n 级数**（不是生成器所用的 Snyder 级数）对 11 个锚点做 EPSG:4547 正算，与生成器 `projectToCGCS2000` 比较：

| 指标 | 结果 |
| :--- | :--- |
| 最大北向差异 | **0.000423 m**（0.42 mm） |
| 最大东向差异 | **0.000496 m**（0.50 mm） |
| 生成器轴向角 | 50.9612° |
| Vincenty 测地起始方位角 | 50.9705° |
| 方位角差 | 0.0093°（约 0.6 m / 4 km 横向） |
| G01→G11 投影直线距离 | **4,115.10 m** |
| G01→G11 Vincenty 测地距离 | **4,115.10 m** |
| 11 点链式距离（投影） | **4,122.71 m** |
| 11 点链式距离（Vincenty） | **4,122.67 m** |

**判定**: 投影数学实现 **PASS**（亚毫米级一致）；但这是变换正确性，不是源坐标精度。

## 5. 几何、面积与通行时间的内部矛盾

### 5.1 分段长度 vs 固定通行时间

由锚点 `s_along` 差得到各段**沿轴长度**约（注意：这是沿江轴投影距离，不是两点间欧氏距离；欧氏链式为 4,122.7 m）：

| 段 | 沿轴长度 (m) | L1/堤顶代码时间 (s) | 隐含速度 (m/s) |
| :--- | ---: | ---: | ---: |
| G01–G02 | 376.1 | 120 | 3.13 |
| G02–G03 | 340.3 | 120 | 2.84 |
| G03–G04 | 347.7 | 120 | 2.90 |
| G04–G05 | 362.7 | 120 | 3.02 |
| G05–G06 | 464.7 | 120 | 3.87 |
| G06–G07 | 536.8 | 120 | 4.47 |
| G07–G08 | 457.2 | 120 | 3.81 |
| G08–G09 | 414.4 | 120 | 3.45 |
| G09–G10 | 443.8 | 120 | 3.70 |
| G10–G11 | 371.6 | 120 | 3.10 |

代码注释称“平地 ~2 分钟”，但 120 s 走完 340–537 m 需要 **2.84–4.47 m/s**，是模型自身自由流速度 1.25 m/s 的 **2.3–3.6 倍**。L2（150 s）和 L3（180 s）同样偏短。  
**结论**: 通道通行时间不是由长度/速度计算的，而是固定常数；这会直接改变规划器/校验器的最短时间流结果。**FAIL**。

### 5.2 面积 vs 几何

区域 `area_m2` 与 `geometry`（像素矩形）之间没有比例换算：

- x 方向比例约 4,115 m / 2,180 px = 1.888 m/px；
- y 方向没有定义物理比例，四级平台 y 坐标是示意分层；
- 因此 160×90 px 的 L1 区域无法推出 36,000–65,000 m² 的面积；
- `area_provenance=estimated` 也确认面积是独立工程取值，不是 GIS 多边形求和。

**结论**: “GIS 地形网格测绘矢量多边形求和”不成立。**FAIL**。

### 5.3 三个“汉口拓扑”的计数不一致

| 表征 | 区域 | 通道 | 出口/闸门 | 面积 |
| :--- | ---: | ---: | ---: | ---: |
| 44 区域生成场景 `hankou-marshland.json` | 44 | **78** | 11 | **733,600 m²** |
| 15 区域基准夹具 `hankou-canonical-scenario.ts` | 15 | **23** | 11 | **180,500 m²** |
| 15 区域微分模型 `differential-model.ts` | 15 | **35** | 11 | **314,000 m²** |
| `GIS_VALIDATION.md` 声称的宏观聚合 | 15 | **42** | 11 | 未给 |
| `ASSUMPTIONS.md` 声称的 `A_total` | — | — | — | **420,000 m²** |

- 夹具头注释写“42 条通道”，实际 `createHankouMarshlandScenario().corridors.length = 23`；
- 微分模型实际 `createHankouMarshlandCorridors().length = 35`（24 flat + 11 stair_up），不是 42；
- 报告把 42 当作“宏观聚合表征”的通道数，两个可能来源都不等于 42。
- 四个面积值（733,600 / 180,500 / 314,000 / 420,000）互不一致，且没有换算说明。

**判定: FAIL**（“双重拓扑表征体系一致”不成立）。

### 5.4 E2E 夹具与真实生成器不一致

`tests/e2e/realworld_hankou/fixtures/gis-pipeline-data.ts`：

**判定**: 143 项 E2E 通过验证的是夹具，不是 `data/scenarios/hankou-marshland.json` 的真实生成管线。**FAIL**（就“E2E 证明真实 GIS 管线”而言）。

## 9. 复审所需的外部证据（BLOCKED）

以下项目在仓库内无法完成，必须由外部资料或现场工作补齐，**不得用现有数据替代**：

1. 11 个闸门的官方坐标/净宽/高程图纸或测量报告（含文号、图号、控制点）；
2. OSM 原始下载文件（`.osm`/`.pbf`）、查询语句、下载时间、SHA-256、ODbL 归属；
3. 武汉市水务局/长江水利委员会的公开通告原文或可引用 URL；
4. 现场全站仪/RTK 控制点，至少 3 个独立检核点；
5. 明确的高程基准（吴淞 vs 1985 国家高程基准）及换算关系；
6. 堤防横断面、亲水台阶踏步几何、桥梁/天桥结构参数；
7. 若要主张 0.1 m 精度：独立的重复测量与误差统计（RMSE/最大偏差），而不是投影公式。

在上述证据到位前，所有“实测”“0.1 m”“54 m”“3.6 km”“0.42 km²”表述均应降级或删除。
