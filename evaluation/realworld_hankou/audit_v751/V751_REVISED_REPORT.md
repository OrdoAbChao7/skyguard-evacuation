## 1. 修订说明

### 1.1 为什么修订

原 V7.5 报告存在三类问题：

1. **数字与原始数据不一致**：makespan、queue、validator 通过率、FSM 遵从度、文件大小、测试构成等；
2. **证据等级被拔高**：硬编码锚点/工程假设被写成“实测/测绘台账”；投影变换正确被写成“0.1 m 源数据精度”；合成噪声被写成“真实路径抖动”；
3. **实验构造失效**：750 轮“五算法对比”实际是一个规划器 + 五个标签；规划器输出未进入仿真；仿真质量不守恒；validator 通过率硬编码；ST-05 使用真值 oracle。

### 1.2 修订范围

- 只复核与修订**报告表述**；
- 不修改原始实验数据、不修改算法参数、不修改冻结证据；
- 不开发新功能；
- 不执行 commit/push/PR/tag。

### 1.3 证据等级

| 等级 | 含义 |
| :---: | :--- |
| **PASS** | 仓库内代码/数据/测试可直接验证，可按限定口径使用 |
| **PARTIAL** | 方向成立，但依赖假设/口径/二手来源，必须加限定 |
| **BLOCKED** | 仓库内无法核实，需外部证据；**不得写成已验证** |
| **FAIL** | 与代码/原始数据矛盾，或确定性表述无证据；必须删除或重写 |

## 6. 算法基准证据

### 6.1 750 条记录与复现

- 750 条记录存在，5×5×30，无缺失；
- 隔离副本重跑：627/750 完全相同，123/750 仅 `solve_ms` 不同；流量字段 750/750 相同；
- `solve_ms` 是 `baseSolveMs × 策略乘数 + rng` 的合成值：STATIC 3–7、DYNAMIC 5–8、V74 25–31、TIME_EXP 恒 10、V73 恒 16。

**判定**: 记录完整性 **PASS**；独立实验 **FAIL**。

### 6.2 五个标签不是五个算法

- 每个策略只调用一次 `planEvacuation`；
- `planOutput` 只用于初始校验与 FSM，未进入 30 分钟仿真；
- 仿真分流由硬编码 `arrivalRate` 决定；
- V73 与 TIME_EXP 在 150/150 对记录（5 场景 × 30 种子）中流量字段逐位相同；
- V74 在 ST-01/02/04/05 与 TIME_EXP 逐位相同，仅 ST-03 不同（arrivalRate 0.072 vs 0.085，转移 ×0.97）。

**判定**: “5 算法对比” **FAIL**。

### 6.3 质量不守恒

| 指标 | 结果 |
| :--- | :--- |
| 正残差探针 | 75 / 75 |
| 最小残差 | 7,432 人 |
| 最大残差 | 393,912 人 |
| completed / expected | 1.463 – 4.638 倍 |
| 平均 completed / expected | 2.955 倍 |
| unserved ≠ 0 | 0 / 75 |

原因：

1. `arrivalRate` 未乘 DT（0.1 min），等效 72–140%/分钟；
2. 队列已存入 `bottleneckQueues`，但仍留在 `currentPops`，下一步重复计费；
3. `unserved = finalRemaining` 不含队列，恒为 0。

**判定**: 质量守恒 **FAIL**。

### 6.5 100% 校验的真实含义

V74 的 150/150 通过：

- 校验对象是**初始 plan**，不是 30 分钟仿真；
- ST-05 用 `currentPops` 真值替换无人机观测（oracle），confidence 0.92；
- STATIC/DYNAMIC 的通过率完全由场景 ID 决定；TIME_EXP/V73 由“非 ST-05 且 baseValResult.valid”决定；
- 仿真本身质量不守恒，`unserved=0`。

因此只能写：

> “在当前 synthetic sample 中，V7.4 的初始方案 150/150 通过约束校验；ST-05 使用了真值观测，不构成独立感知验证，也不构成现实安全保证。”

不得写“绝对安全/100% 人员安全/全场景 0 违规”。

FSM 同样不是 100%：五个策略的场景预期匹配都是 120/150（80%）；ST-03 的 `expected_state` 是 REROUTE，但五个策略实际都输出 NORMAL。这是共同的场景建模/预期标注问题，不是 V74 独有的优势。

**判定**: **FAIL（作为安全保证）**。

---

## 7. 安全架构（可保留的真实成果）

以下结论不依赖基准构造，代码与测试可直接验证：

1. **四态状态机**：NORMAL / REROUTE / DEGRADED / REJECT；优先级 `DEGRADED > REJECT > REROUTE > NORMAL`；
2. **独立校验器**：`validator.ts` 独立重建时间流/容量约束，不读取 planner 的 `status/feasible`；
3. **未知不可用**：`C_FLOOD_ESCAPE_UNKNOWN` 容量 null、status unknown，不被分配；
4. **人工审批**：Agent 只能创建待审批工单，不能审批/派发/控制无人机；
5. **基线保护**：`validator.ts`、`evacuation-planner.ts`、`state-machine.ts` 相对 `4025ac1` 的 Git blob SHA-1 一致，`git diff` 为空；
6. **回归测试**：核心 34/34 + API/provider 13/13 通过；
7. **诚实降级**：无 NPU → `ASCEND_UNAVAILABLE`；无租户 → `LOCAL DEMO / AGENTARTS UNAVAILABLE`。

**判定**: 架构 **PASS**；但“架构正确”不等于“基准证明算法安全”。

## 10. 结论与建议

### 10.1 对外表述建议

对华为 ICT 答辩，建议把 V7.5 定位为：

> “一个以汉口江滩为**公开资料参考 + 工程假设**的研究原型：安全架构、四态状态机、独立校验器、未知通道隔离、人工审批是真实可验证的；GIS 投影实现与测试资产是真实可复现的；但 750 轮算法对比、真实地理精度、100% 安全校验尚未达到可对外宣称的证据等级。当前版本更适合展示**安全架构与负结果**，而不是‘五算法全面领先’或‘真实场景高保真’。”

### 10.2 下一步（本轮不做）

1. 修复仿真质量守恒（arrivalRate 乘 DT；队列从 currentPops 扣除；unserved 计入队列）；
2. 让 `planOutput` 进入 30 分钟仿真；
3. 实现至少 3 个真正独立的规划/控制策略；
4. 移除 validator 硬编码与 ST-05 oracle；
5. 修复 ST-04 事件应用与通道 ID；
6. 提高压力场景密度，触发反压；
7. 落盘 OSM 原始文件/哈希/ODbL；补水务局文号/控制点；
8. 统一 4.115 km / 0.7336 km² / 100.5 m 口径；
9. 用 `sensitivity-results.json` 重写敏感性表；
10. 所有报告数字由脚本从原始 JSON 自动生成。

### 10.3 最终判定

# **INTEGRITY CONCERN**

核心证据链不成立；但安全架构与工程实现有真实价值。完成 §10.2 后重新审计，才可能升级为 **CLEAN WITH CORRECTIONS**。
