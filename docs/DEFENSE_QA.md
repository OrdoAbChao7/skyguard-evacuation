# 技术答辩问题库（30 问 + V6.5 追加）

1. **VoI 的数学定义？** 贝叶斯后验 + 熵 + 预期风险损失降低 − 时间/资源/失败成本；参数全部来自场景。
2. **VoI 一定更好吗？** 不。模拟中成本更低，但风险降低略低；多区域总收益高、单位效率可能低。
3. **概率从哪来？** 场景 JSON 的先验/似然/损失矩阵，加载时校验归一化；LLM 不生成。
4. **证据冲突怎么办？** 10 分钟窗口内相反信息性证据标记冲突，后验与先验 50/50 折扣。
5. **调查失败怎么办？** 最大尝试次数 + 冷却 + 指数退避；预算耗尽停止。
6. **多区域模型是什么？** 区域图 + 容量/距离边权 + 风险传播 + 覆盖权重；是启发式，不是人群动力学。
7. **多区域一定更优？** 30 种子下总风险降低约 4.6×，成本约 2.3×；V6.2 轮换目标效率 +0.0917，V6.1 同目标效率不显著——结论依赖目标策略。
8. **为什么需要独立 Validator？** 规划器不能自我认证；Validator 自行重建 15 类硬约束。
9. **故障注入结果？** 5/5 检出（超容量、未知出口、未知通道、负人数、重复 route id）。
10. **四态优先级？** DEGRADED > REJECT > REROUTE > NORMAL；数据不可信不下“不可行”结论。
11. **Agent 会越权吗？** 只能创建待审批工单；审批/派发需 admin/operator；接单/反馈需 staff 且仅本人工单。
12. **审批后环境变化？** 工单记录上下文版本，变化后 stale，派发阻断，管理员 revalidate。
13. **重复调用会产生重复任务吗？** 幂等键；MCP 测试验证重复创建返回同一工单。
14. **预测方法？** v3 滚动验证选择 persistence/EMA/linear/damped/blend；区间用 h 步误差 95 分位 ×1.5。
15. **预测准确率？** 无真实标注，不能给真实精度；合成 5 分钟自适应 MAE 59.5，持久化 58.5。
16. **区间覆盖率？** 2/5/10 分钟约 91.5%/84.1%/79.1%，未达 95%，不能用于安全告警。
17. **邻居信息预测？** 合成相关序列相对改进 4.8%/5.1%/8.4%；真实场景未验证。
18. **人群计数精度？** CPU 路径是运动前景计数，无标注；不能声称准确率。
19. **如何接入 P2PNet/CSRNet？** 提供数据集/标注/评测 CLI（MAE/RMSE/NAE、定位 P/R/F1），未附带数据与权重。
20. **MCP 安全？** Zod Schema、角色、超时、审计、结构化错误码、幂等；无文件/命令能力。
21. **AgentArts 接入了吗？** 适配器/健康探测/契约/运行时接线完成；无租户与官方 API 文档，**未实机**。
22. **昇腾状态？** 仅环境探针与外部推理契约；无 NPU/CANN/`.om`，未实机。
23. **无人机？** 工单请求/审批/模拟反馈；无真实飞控。
24. **场景能换吗？** 能。区域/通道/出口/规则/人员/无人机/调查策略/工具清单都在 JSON。
25. **并发能力？** 单进程内存状态；限流是进程内；多实例需共享存储/分布式限流。
26. **持久化？** 可选工单 JSON 快照（非数据库，无事务）；安全状态仍在内存。
27. **统计数据怎么保证？** 固定种子、多种子、Bootstrap 置信区间、原始 JSON、失败案例。
28. **实验是否选择性报告？** 报告弱点：预测突增差、区间不足、VoI 权衡、多区域效率。
29. **真实数据边界？** 没有真实场馆/人流/视频/平台/硬件；全部合成。
30. **距离全国一等奖还差什么？** 真实场景测绘与数据、AgentArts 租户实机、CANN 设备、公开数据集评测、正式安全评审与演练。

## 追加：评委最可能追问的尖锐问题

31. **多区域 VoI 为什么值得用？**
   30 种子下总风险降低 0.2154 vs 0.0472（d_z=2.06），覆盖 6.74 vs 1.59 区域；代价是成本约 2.3×。
   适合风险传播强、预算充足的场景，不是无条件更优。

32. **为什么单位成本效率不一定更好？**
   多区域动作（无人机/全局预测）单次成本高；收益按覆盖权重求和会被稀释。
   V6.2 轮换目标效率差 +0.0917，V6.1 同目标效率不显著——效率结论依赖目标策略，不能无条件宣称。

33. **序贯重试真的提高成功率吗？**
   同 2 次尝试预算下，重试与不重试均为 92%；91% vs 68.6% 是 2 次 vs 1 次尝试的差异。
   重试的价值在于动作可用性/时间预算，不是无限提高成功率。

34. **为什么简单预测模型可能优于复杂模型？**
   突增/周期峰值不可从历史外推；持久化/EMA 更稳。严格滚动下自适应在 stable/decline/missing 更好，
   surge/periodic persistence 略优——模型选择必须按场景验证。

35. **风险传播系数如何标定？**
   当前**没有标定**。边权=容量因子×距离因子，系数为工程启发式；敏感性实验显示 damping/覆盖权重会改变排序。
   没有真实人群迁移数据前，不得解释为真实迁移概率。

36. **没有真实场地数据，如何证明应用价值？**
   只能证明机制、可复现性与失效条件，不能证明现场效果。真实测绘/人流/平台/硬件是下一步阻塞项。

37. **AgentArts 和昇腾是否真正参与系统运行？**
   没有。AgentArts 是适配器 + 契约测试；昇腾是探针 + 推理契约；界面明确 `LOCAL DEMO` / `UNAVAILABLE`。

38. **来源里有些 URL 404/403，怎么处理？**
    V6.2 审计 28/38 可达；S15/S18 华为页面 404，8 条 403/网络失败。全部标记未核验，不当作已验证证据；
    引用前必须替换或人工确认。

39. **原始数据如何治理与复现？**
    raw/summary/report 分层；V6.1 冻结 SHA-256；V6.2 独立目录；`verify:evidence` 134 项复算；
    `manifest:evidence` 46 文件校验；gzip 估算 1.66 MiB。

40. **为什么只是候选版本，不是生产就绪？**
    真实场地/人流/视频、AgentArts 租户、昇腾设备、Docker/CI、安全认证均未验证；
    当前只证明机制、可复现性与失效条件，不能证明现场安全或生产可用。

## V6.5 追加：资源、状态与预测

**Q1：工单创建就预留人员，会不会把一个还没审批的任务锁死？**
预留有 TTL（场景配置，默认 15 分钟），过期自动释放；审批、派发、接单都会复核
人员状态与场景版本。拒绝/取消/失败都会释放；完成才把预算结算为已用。
这比“审批后才占人”更早暴露资源冲突，但不会永久锁死。

**Q2：并发创建两个工单抢同一个人怎么办？**
创建是单进程同步操作；第一个成功后该人员状态变为 `reserved`，第二个显式请求同一人
会得到 `RESOURCE_UNAVAILABLE`。测试覆盖了 `Promise.allSettled` 下只成功一个。
多实例并发仍未支持，已明确写在限制中。

**Q3：幂等键能防止重复工单吗？同键不同参数呢？**
可以。幂等键绑定规范化请求参数的 SHA-256 指纹：同键同参返回同一工单，
同键异参返回 409 `IDEMPOTENCY_CONFLICT`，不会悄悄复用旧结果。

**Q4：重启后旧审批会不会复活？**
统一状态快照同时保存上下文版本、预留与工单状态；恢复后 `getWorkOrder` 会重新计算
stale。审批/派发仍要求上下文与场景版本一致；损坏或未来版本状态文件会拒绝启动，
不会以空状态继续。实机测试验证了创建→重启→恢复，以及双副本损坏 exit 1。

**Q5：为什么不直接用数据库/消息队列？**
当前是单实例研究原型，目标是可审计、可复现的原子文件快照与故障行为；引入数据库会
增加部署与评审复杂度，但不能替代真实多实例验证。限制已明确，后续可迁移到 SQLite/事务库。

**Q6：预测模型到底哪个最好？**
没有单一最好。V6.5 实验中自适应在配对平均上优于所有基线，但 stable/decline/periodic/noisy
上 linear 最佳，surge 上 persistence 最佳，missing 上 EMA 最佳。surge 的 95% 区间覆盖率
只有 0.738，所以不能用区间做告警阈值。我们保留负面结果，不挑选有利场景。

**Q7：预测不可靠时系统怎么办？**
区间相对宽度超过场景阈值或数据不足时，`reliability.status=failed`，VoI 的预测动作不可用；
安全四态仍由观测可信度决定，预测不会替代独立校验或四态判定。

**Q8：CityStreet 数据不是有区域人数吗？为什么不能直接用于安全？**
它是无真值的派生显示数据，配准近似、许可未核验；区域面积不是场景标定面积。
适配器只在 surveyed 标定、面积与场景区域一致、置信度足够时才生成可信观测；
否则写入 `valid=false` 观测并进入 DEGRADED。我们展示面积/密度，但明确标注“未标定”。

**Q9：AgentArts 现在已经接入了吗？**
没有。官方运行时契约、会话头、重试、SSE、越权拒绝和反馈续接都有本地 stub 测试；
但没有真实租户、凭证与平台 Trace。界面区分“可达性”和“业务闭环”，健康探测成功不会
把业务闭环标为已验证。

## V7.0 追加：预测、动态规划与联合 VoI

**Q1：为什么 ensemble_v70 没有在所有场景胜出？**
A：没有任何单一模型全场景最优，这是本实验的明确结论。集成显著优于 persistence/EMA/linear/Kalman/在线 LSTM，
但显著劣于 ARIMA/Holt-Winters/旧自适应；stable/missing/noisy 最佳为在线 LSTM，surge/periodic 为 Holt-Winters，
decline 为 linear，regime_shift 为 ARIMA。我们保留全部对照与负结果，不宣称“集成全面最优”。

**Q2：surge 的 95% 区间覆盖率只有 0.748，还能用吗？**
A：不能用于安全告警阈值。我们显式报告欠覆盖，并在可靠性失败时阻断 VoI 预测动作；
安全四态仍由观测可信度决定，预测不替代安全判定。

**Q3：预测和队列反馈为什么没有提升 MPC？**
A：在“即时响应、每 2 分钟重规划、无调度延迟”的模型中，反应式重规划已经足够，预测与队列反馈没有显著增量
（Holm p=1 / 0.49）。这不等于预测无用；真实系统存在人员调度、预留提前期与通信延迟，需另行建模与验证。
我们保留该负向结果，不调参制造优势。

**Q4：联合 VoI 比现有多区域 VoI 更好吗？**
A：没有。总风险降低略低（−0.0026），最坏区域风险略低（−0.0007），效应量很小。
联合 VoI 是启发式近似，不是联合 POMDP 精确解；Oracle 上界显示仍有很大改进空间。

**Q5：MPC 会不会绕过独立校验？**
A：不会。只有对应当前观测的第一步执行独立校验；包含预测到达或后续控制步的路线标记为条件投影，
不声明“已验证”。安全发布仍走原有 recompute + Validator 流程。

**Q6：BPR 和出口服务衰减参数从哪来？**
A：都是未标定的启发式（BPR a=0.15,b=2；服务衰减 factor=1/(1+q/(μ·5))，下限 0.5）。
我们明确标注，不把它们表述为实测人群速度或服务率；真实标定是后续工作。

**Q7：为什么新增 Dijkstra 求解器？**
A：受限出口集合下，SPFA 的零费用残量环会导致路径回溯死循环。研究求解器改用 Dijkstra + 势函数；
安全主链路的 SPFA 规划器保持原样，既有 199 个测试全部通过。

**Q8：这些结果能说明真实场馆疏散效果吗？**
A：不能。全部是合成场景、合成入流与未标定参数；没有真实场馆时序、标定速度/服务率或现场演练。
它们只说明在给定模型与参数下的相对表现，以及方法的可实现性与可复现性。
