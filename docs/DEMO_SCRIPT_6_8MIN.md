# 6–8 分钟演示脚本

> 目标：用可运行的系统证明三个创新，而不是念 PPT。
> 全程使用合成数据；必须口头说明“非真实场馆/平台实测”。

## 0:00–0:45 问题与定位

- 大型活动散场：固定巡查看不过来、信息缺失时凭经验、调度靠喊话。
- SkyGuard：**风险/信息价值驱动主动调查 + 可信安全决策 + 人工审批闭环**。
- 明确边界：研究原型，不替代现场指挥。

## 0:45–1:45 架构一页

展示 `docs/MVP_ARCHITECTURE.md` 图：

- 感知 → 预测 → VoI → 工具（MCP）→ 人员/工单 → 审批 → 反馈 → 重新评估；
- 安全内核：规划器 + 独立 Validator + 四态状态机；
- Agent 只组织工具，不计算路线、不审批。

## 1:45–3:00 场景 A：正常散场（一键推演）

1. 打开 `/`，点「推演 A」；
2. 指出：8 区域、回放观测、NORMAL、预测东看台上升；
3. Agent 判断“数据可信”，**不发起调查、不建单**；
4. 强调：不是每次都要调用工具，避免无意义调查。

## 3:00–5:30 场景 B：局部积聚 + 信息不确定（核心）

1. 点「推演 B」：东看台低置信观测 → DEGRADED；
2. Agent 控制台：
   - 摄像头不可用 → VoI 排序（现场核查/无人机分数）；
   - 创建现场核查 + 无人机请求（均为待审批）；
3. 切到「审批中心」：管理员批准、自动派发；
4. 点「工作人员移动端」或输入 `STF-02 / 1002`：
   - 接单 → 开始 → 提交反馈（920 人，0.95）；
5. 回到大屏：状态脱离 DEGRADED；再点「运行 Agent」：
   - 不再重复调查，生成疏导工单（待审批）；
6. 指出工单时间轴：`PENDING_APPROVAL → APPROVED → ASSIGNED → ACCEPTED → IN_PROGRESS → COMPLETED`；
7. 强调：反馈写回 `field_report` 观测并触发重新评估。

## 5:30–6:30 场景 C：不可信/容量不足

1. 点「推演 C」；
2. 先显示 DEGRADED（全部观测无效）→ 再 REJECT（高密度 + 关闭东西出口）；
3. 指出：无已验证路线、未解决人数、人工介入说明；
4. 强调：宁可拒绝，不发布不可行路线。
