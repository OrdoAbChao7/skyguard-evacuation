# SkyGuard V7.4 实验报告

> 运行：`v74-final-20261110T105851`。30 种子 × 8 场景（稳定性）、30 种子 × 4 机制（检测）、夹具（标定/生产）。
> 数据性质：**合成场景 + 合成入流 + 夹具观测**。所有数字仅说明本实现在本模型中的行为，不外推到真实场馆。
> 原始数据：`evaluation/v74/v74-final-20261110T105851/`（`*_rows.json`、`*_summary.json`、`*_metadata.json`、`*_MANIFEST.json`）。

## 1. 研究问题

| 编号 | 问题 | 预注册判据 |
| --- | --- | --- |
| Q1 | 执行感知门控能否在不增加完成时间的前提下降低切换？ | 切换显著下降且 makespan 差 95%CI 不超 +0.5 分钟 |
| Q2 | Pareto 份额扫描是否给出更好的稳定性—效率折中？ | 切换显著下降，makespan/队列代价有界且可量化 |
| Q3 | 风险触发承诺释放能否在紧急场景及时解除承诺？ | 释放事件出现、未疏散不高于标准 MPC 的 2 倍 |
| Q4 | 风险敏感惩罚是否改变决策？ | 与 V7.3 自适应结果不同 |
| Q5 | 动态容量下稳定性机制是否保持容量安全？ | 容量违规 = 0 |
| Q6 | CUSUM+spike 是否优于 3σ 检测？ | 检测率更高，误报不显著恶化 |
| Q7 | 标定质量模块能否拒绝时钟偏移并检测缺失？ | 超限偏移拒绝、缺失区间被报告 |

## 2. 方法

### 2.1 稳定性基准

- 30 个种子（20261111–20261140）× 8 场景：`baseline_surge`、`exit_failure`、`corridor_closure`、
  `bidirectional_stress`、`multi_zone_surge`、`midrun_exit_failure`、`dynamic_capacity`、`oscillation_stress`。
- 控制间隔 2 分钟、规划视界 10 分钟、最大执行 24 分钟。
- 稳定性配置：迟滞 0.05、切换惩罚 10 人、承诺 6 分钟；自适应基础惩罚 10、队列阈值 100、
  风险折扣 0.5、振荡惩罚 20、风险加权切换；标量化权重 arrival 1 / makespan 0.5 / queueProxy 0.25 /
  exposure 0.05 / switching 0.02。
- 动态容量：走廊 C_NE/C_NW 第 4 分钟后 ×0.5；出口 E_NORTH 第 5 分钟后 ×0.7。
- 预测误差：时间 ±1 分钟、人数 ×[0.8, 1.2]。
- 配对统计：同种子同场景配对差值，10,000 次 bootstrap 95%CI，Cohen's dz，家族内 Holm 校正（α=0.05）。

### 2.2 六策略

- A `legacy_static`：一次规划；
- B `mpc_standard`：标准 MPC；
- C `mpc_adaptive_v73`：V7.3 自适应，无执行门控；
- D `mpc_risk_adaptive`：风险折扣 0.9；
- E `mpc_emergency_release`：最大区域风险 ≥0.5 释放承诺；
- F `mpc_pareto_gate`：份额 0.8/0.6/0.4/0.2 + 门控（makespan +1 分钟、queue +2000 人·分钟）。

但 E/F 的未疏散均值不为 0（2.87/3.81），C 为 0。

### 3.2 Q1：零容差门控

- 严格门控（0 分钟/0 人·分钟）**拒绝全部承诺候选**，系统回退标准 MPC；
- 因此**没有实现「零完成时间代价的切换下降」**；
- 结论：在本执行模型下，承诺保持与完成时间存在真实冲突，不能宣称无代价稳定性。

这是 V7.4 最重要的负结果：先前有理由怀疑 Pareto 候选可以在不损失效率时降低切换，但实测不支持。

### 3.3 Q2：Pareto 门控

- 切换下降 51.9%（1983/3821），完成时间代价 +0.575 分钟（+5.8%），队列 +4.3%；
- 门控平均每场景拒绝 3.90 个候选，说明门控在真实地约束选择；
- 振荡下降 76.2%（436/572）；
- 安全违规 0.0125 次/场景（标准 0.0542），容量违规 0。

Pareto 门控是「有界代价」的稳定性方案，不是免费方案。

### 3.4 Q3：紧急释放

- 平均 2.62 次释放/场景；未疏散 2.87（C 为 0，B 为 16.47）；
- 完成 +0.408 分钟、队列 +424；
- 在 `exit_failure`、`midrun_exit_failure` 场景未疏散仍为 0，说明释放主要发生在容量压力而非出口失效；
- 释放机制有效，但引入少量未疏散，需在部署中按风险偏好配置阈值。

### 3.5 Q4：风险敏感惩罚

- D 与 C 在全部 240 个配对样本上**逐指标完全相同**；
- 原因：riskDiscount 0.9 只缩放惩罚，未跨过任何决策阈值；
- 结论：该参数在此场景集下无效，不能声称「风险敏感惩罚优于自适应」。保留为负结果。

### 3.6 Q5：动态容量

| 策略 | 容量违规 | 安全违规 | 未疏散 | 完成 |
| --- | ---: | ---: | ---: | ---: |
| A | 6.43 | 7.43 | 781.03 | 24.0 |
| B | 0 | 0 | 0 | 9.667 |
| C | 0 | 0 | 0 | 10.0 |
| F | 0 | 0 | 0 | 10.0 |

动态容量下规划/执行/复核口径一致：所有 MPC 变体容量违规为 0；静态规划在动态容量下严重失效（证实容量口径一致性的必要性）。
稳定性收益在该场景缩小：C 切换仅从 3226 降至 3073（−4.7%），说明动态容量压缩了可切换空间。

### 3.7 场景异质性（切换人数，B/C/E/F）

| 场景 | B | C | E | F |
| --- | ---: | ---: | ---: | ---: |
| baseline_surge | 3612.67 | 914.73 | 3289.57 | 1377.93 |
| exit_failure | 4700.80 | 1901.07 | 4371.33 | 2049.00 |
| corridor_closure | 3517.97 | 768.43 | 3069.27 | 1424.33 |
| bidirectional_stress | 3222.57 | 634.03 | 2901.60 | 1122.17 |
| multi_zone_surge | 3802.97 | 783.47 | 3600.30 | 1395.10 |
| midrun_exit_failure | 4745.97 | 1724.30 | 4219.63 | 2334.97 |
| dynamic_capacity | 3225.97 | 3072.93 | 3081.03 | 3124.37 |
| oscillation_stress | 3737.13 | 1153.10 | 3450.70 | 1873.43 |

- 紧急释放（E）在多数场景仅小幅降低切换（−1% 至 −9%），但在 `dynamic_capacity` 几乎无效；
- Pareto 门控（F）稳定在 −40% 至 −65%，但 `midrun_exit_failure` 代价最高（切换仍 2335）；
- 自适应（C）在 `dynamic_capacity` 收益最小，提示承诺份额应与容量波动联动。

### 3.8 振荡

- 标准 MPC 振荡 571.89 人；C 93.35（−83.7%）；F 136.08（−76.2%）；E 467.12（−18.3%）；
- C 相对仅承诺保持（commitment-only 对照，见 `mechanism.oscillation_gain_adaptive_vs_commitment`）
  额外减少 373.77 人振荡 [307.13, 440.41]；
- 逐例仍有振荡：C 在 `oscillation_stress` 场景 65.57 人，说明迟滞不能消除所有反复。

### 3.9 求解延迟

- F 平均 40.85 ms/步（含 18.45 个候选的多次求解），p95 未在本次汇总单列；
- 若部署要求亚 10ms 规划，需要缓存/剪枝；当前仅证明研究原型可交互。

## 4. Surge / regime 检测

| 机制 | CUSUM+spike 检测率 | 3σ 检测率 | CUSUM 中位延迟 | 3σ 中位延迟 |
| --- | ---: | ---: | ---: | ---: |
| stable | 0 | 0 | — | — |
| surge | **1.000** | 0.767 | 5 | 5 |
| regime_shift | **1.000** | 0.733 | 7 | 7 |
| noisy | 0 | 0 | — | — |

误报：stable 段种子误报率均 33.3%；每 100 步误报 CUSUM 0.61 / 3σ 0.56（stable）；
surge 段 CUSUM 0 / 3σ 0.33；regime 段 CUSUM 0.33 / 3σ 0.33；noisy 段 CUSUM 0.78 / 3σ 0.50。

结论：检测率提升明确（+23.3/+26.7 个百分点），延迟相同；代价是 no/surge 段误报略高。
Noisy 机制两者均 0 检测，说明高噪声下阈值方法失效，这是已知限制。

## 5. 标定质量（夹具）

- 时钟同步：接受 3，拒绝 1（provider-slow，偏移 90s > 30s 上限）；应用偏移 0s/3s；
- 缺失区间：检测 1 段（R_NORTH_STAND，110s，期望 1 样本）；
- 传感器可靠性：provider-a 0.3447、provider-b 0.14（代理分数，非准确率）；
- 观测质量：覆盖率 0.125（仅 1/8 区域有观测），过期 1，无效/重复 0；
- 动态容量计划：2 条区间通过校验；第 5 分钟走廊 0.5、第 12 分钟出口 0.7、第 20 分钟恢复 1。

## 9. 有效性威胁

1. **合成数据**：场景、入流、误差模型均由本仓库生成，不能代表真实场馆；
2. **单一执行模型**：FIFO+BPR+出口衰减未标定，切换收益随模型变化；
3. **场景集有限**：8 场景无法覆盖所有拓扑/事件；
4. **参数选择**：门控 1min/2000 为预先设定，未做完整敏感性网格（V7.3 已做部分）；
5. **未做跨数据集**：预测/检测无真实视频或轨迹验证；
6. **平台/硬件缺失**：AgentArts、Ascend 结论只到适配器/CPU 层面；
7. **多重比较**：使用 Holm 校正，但场景层未做分层检验。
