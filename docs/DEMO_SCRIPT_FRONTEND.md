# SkyGuard 前端演示分镜（6–8 分钟）

> 版本基线：`v7.5.0-research.1`（2026-11-14，汉口江滩 44 区域场景）
> 目标：用**真实前端操作**证明三个创新，而不是念 PPT。
> 数据边界：场景与观测均为合成数据；感知回放为非实时派生数据；AgentArts/昇腾/无人机未实机。
> 关联材料：[DEMO_SCRIPT_6_8MIN.md](DEMO_SCRIPT_6_8MIN.md)（内容脚本）、[MVP_ARCHITECTURE.md](MVP_ARCHITECTURE.md)、[MVP_LIMITATIONS.md](MVP_LIMITATIONS.md)。

## 1. 录制原则

- **70% 界面操作，20% 证据，10% 边界声明**。架构图最多出现 15 秒。
- 所有状态变化必须由真实点击触发，不剪辑伪造、不事后补录状态。
- 每个关键状态停留 2–3 秒，等评审看清再操作。
- 画面永久带角标：`合成数据 · 研究原型 · 非实时`。
- 视频里的每个数字，报告里必须能指到对应章节。

## 2. 录制前准备

### 2.1 环境与账号

```bash
npm run setup
npm run dev          # 后端 8010 + 前端 5173
```

| 身份 | 入口 | 用途 |
| --- | --- | --- |
| 管理员 | `/login` | 运行 Agent、批准/派发工单 |

审批、派发、运行 Agent 都需要管理员 JWT；接单/执行/反馈需要工作人员 JWT。

### 2.2 画面设置

- 浏览器 1920×1080、100% 缩放，隐藏书签栏，关闭通知与弹窗。
- 左侧窗口：管理员 `/`；右侧窗口：`/staff`，DevTools 设备模拟 390×844（手机比例）。
- 指挥大屏默认「指挥白」；录制前点右上「界面配色」→「深空」，与登录页、移动端画面更统一（选择保存在当前浏览器）。
- 「现场协同管理」顶部是「推演 A / B / C」演示条，点一下即载入场景；Agent 控制台内容在面板内滚动，不必把整页拉得很长。
- 「现场协同管理」内还有「系统仿真」面板（9 步时间轴）：从冷启动到事件解除，逐步写入合成观测、重算、触发 Agent 与人工工单。启动需要先在 `/login` 登录管理员；它不会自动审批或派发任何工单。可作为 S5 的替代或加演，详见第 9 节。
- 录制工具：OBS，1080p，鼠标点击高亮；剪辑时对关键数字做 1.2× 放大。
- 自动录屏（备用素材）：`node frontend/e2e/capture-submission.mjs --out submission/demo-run --video --slowmo=150` 会跑完整 9 步仿真，输出 `video-admin.webm`（1600×1000）与 `video-staff.webm`（430×920）；无旁白，仅作备份与证据。
- 中文字幕全程保留；专有名词首次出现加注释。

## 4. 逐段脚本

### S1 登录（0:00–0:25）

**画面**：`/login` 登录页，左侧品牌叙事，右侧「安全决策操作登录」。

**操作**：输入管理员用户名/密码 → 点「登录」。

**旁白**：

> 这是一个研究原型，不是应急指挥系统。所有演示数据都是合成的。系统区分管理员和工作人员身份，审批与执行是两条权限链。

**注意**：密码输入时打码或提前登录，不要拍到屏幕上的真实凭证。

### S2 首屏（0:25–1:10）

**画面**：`/` 指挥中心。

**操作**：不点击，缓慢移动鼠标。

**指认顺序**：

1. 顶部状态徽标：刚启动时是 `DEGRADED`（感知降级 · 尚未收到任何观测），这是 fail-closed；推演 A 后才会变为 `NORMAL`；
2. 五联 KPI：感知区域、观测人数、高风险区域、可信方案、推理链路；
3. 左栏「各区域观测」：人数、密度、置信度、时效、来源；
4. 中栏「场馆态势」：区域、通道、出口、风险着色；
5. 右栏「独立校验结果」「发布状态」「人工介入」。

**旁白**：

> 一屏能看完感知、态势和决策。刚启动时没有任何观测，系统默认降级，不假装知道现场情况。注意右侧的发布状态和人工介入，它们由独立校验和四态状态机决定，不是 Agent 决定的。

### S3 地图交互（1:10–1:35）

**操作**：

1. 点地图工具栏「图层」，勾选「风险区域」和「已验证路线」；
2. 任选一个有观测的区域（如 `R_S04_L1_CREST`）；
3. 出现区域详情卡：风险、人数、密度、置信度、时效、来源。

**旁白**：

> 地图不是装饰图。每个区域的人数、密度、置信度和数据来源都能点开；没有观测的区域不会被当成安全。

**顺带指认**：右侧「视频与感知画面」显示「视频源未接入 / 非实时画面 / SIGNAL OFFLINE」。这是刻意保留的诚实占位，不要跳过。

### S4 场景 A：正常散场（1:35–2:35）

**操作**：

1. 向下滚动到「现场协同管理」；
2. 点「推演 A」；
3. 回到首屏看状态变为 `NORMAL`（常态运行 · 方案已通过独立校验）；
4. 在「Agent 控制台」查看：安全状态、信息缺口、调查轮次、工具调用 Trace；
5. 指一下「短时人流预测」「摄像头状态」「工作人员」。

**旁白**：

> 正常场景下，Agent 判断数据可信，不发起调查、不创建工单。不是每次都要调用工具——避免无意义调查是设计目标之一。

**停留点**：`调查轮次 0`、`信息缺口 否`。

### S5 场景 B：局部积聚 + 信息不确定（2:35–4:35，核心）

#### S5.1 触发降级（2:35–2:55）

1. 点「推演 B」；
2. 顶部徽标变为 `DEGRADED`（感知降级 · 不得基于不可信数据发布新路线）；
3. 右栏「不可信区域」计数上升，「发布状态」变为禁止，「人工介入」变为需要。

**旁白**：

> 低置信观测进入系统后，系统先降级，不拿不可信数据生成安全路线。

#### S5.2 Agent 调查（2:55–3:35）

1. 滚到「Agent 控制台」；推演 B 已自动运行一次 Agent，面板应已显示结果；
2. 指出安全状态、信息缺口、调查轮次、工具调用数与信念熵；
3. 展示 VoI 排序表：动作、VoI、信息增益、Δ风险、时间、资源、可用；
4. 展示「工具调用 Trace」和「Agent 建议」；
5. 指出「审批中心与工单」里新出现的待审批工单（现场核查和/或无人机观察，以实际 VoI 排序为准）。

**旁白**：

> Agent 不直接派人，也不控制无人机。它只按信息价值排序，创建待审批工单。

#### S5.3 人工审批与派发（3:35–3:55）

1. 滚到「审批中心与工单」；
2. 切到「待审批」页签，选择一条现场核查（或无人机观察）工单；
3. 点「批准」，再点「自动派发」；
4. 点「查看流转」，展示 `PENDING_APPROVAL → APPROVED → ASSIGNED` 时间轴，并记下「指派」字段的工号。

**旁白**：

> 审批是人的动作。工单上下文有版本，数据变化会让工单过期，需要重新确认。

#### S5.4 工作人员闭环（3:55–4:20）

切到右侧 `/staff` 窗口：

1. 用工单「指派」字段里的工号登录（示例常用 `STAFF_GATE_02 / CODE_G02`）；
2. 「我的任务」中点「接单」→「开始执行」；
3. 点「提交反馈」，填现场人数（如 3500）、置信度（0.95）、说明一句；
4. 点「提交并完成」。

**旁白**：

> 反馈不是聊天记录，它会写回安全域成为一条观测，并触发重新评估。

#### S5.5 状态恢复（4:20–4:35）

回到 `/`：

1. 左侧观测表出现 `field_report` 来源（该区域变为可信）；
2. 审计时间线新增记录；
3. 顶部状态是否离开 `DEGRADED`，取决于其它区域观测是否仍在 90 秒可信窗口内：
   - 仍在窗口内：状态恢复为 `NORMAL`；
   - 已超过窗口：系统继续 `DEGRADED`，这是 fail-closed 的正确行为，据实讲解，不要重跑场景伪造恢复；
4. 若状态已恢复，再点一次「运行 Agent」：不再重复调查，生成疏导工单（待审批）。

**录制提示**：演示 B 后尽快完成审批与反馈；若等待超过 90 秒，观测过期会让系统保持降级。这不是故障，可以正面说明“过期数据不参与发布”。

**旁白**：

> 闭环完成后，系统不会重复调查同一缺口；新的动作仍然是待审批。

### S6 场景 C：不可信 + 容量不足（4:35–5:25）

**操作**：

1. 点「推演 C」；
2. 先观察 `DEGRADED`，再观察 `REJECT`（安全拒绝 · 不存在满足全部硬约束的方案）；
3. 指右栏「独立校验结果」的拒绝原因；
4. 指方案区的候选方案与未解决人数；
5. 指事件列表中的出口关闭事件。

**旁白**：

> 数据不可信时降级；数据可信但硬约束无法满足时拒绝。系统不会为了好看发布一条不可行路线。

**停留点**：`发布状态 禁止`、`无已验证路线`、`未解决人数`。

### S7 感知回放与多区域（5:25–6:10）

**操作**：

1. 滚动到页面下半部「业务闭环与感知回放」；
2. 找到「感知回放 · 单机位派生数据」面板；
3. 指认徽标：`DEMO 回放 · 非实时`、`无真值标注`、`许可 UNVERIFIED`、`未标定映射`；
4. 点播放，展示帧号、点位、区域估计人数；
5. 快速带过「多区域协同调查」的优先级表和联合 VoI 排序。

**旁白**：

> 感知回放只证明“数据 → API → 前端展示”链路可用。它没有逐帧真值，也不是实时视频，不能用来报精度。

### S8 证据（6:10–6:50）

切到终端（只停留 15–20 秒）：

```bash
npm test
npm run verify:evidence
```

**画面**：后端测试全通过（录制当天以实际输出为准，当前为 330 项）、证据校验通过（当前 178/178）。

**旁白**：

> 这些不是截图，是仓库里可以重新跑出来的结果。冻结实验、主张等级和负结果都保留在 evidence 与 CLAIMS 里。

### S9 边界声明（6:50–7:20）

**画面**：回到 `/`，停在「LOCAL DEMO」或「AGENTARTS UNAVAILABLE」徽标。

**旁白**：

> AgentArts 只完成了运行时契约，没有真实租户；昇腾没有 NPU 实机；无人机只有工单闭环，没有飞控；场景是合成的。这些限制在文档里逐条列出，我们不把未验证说成已验证。

## 5. 剪辑规范

- 每个镜头单独录，失败就重录，不拼接状态。
- 状态变化前后各留 1 秒静止画面，方便评审看清。
- 关键数字加放大圈注：不可信区域数、发布状态、工单状态、未解决人数。
- 字幕与旁白一致；不要用“实时监测”“真实场馆”“已控制无人机”等词。
- 片尾放一页静态卡片：系统版本、仓库地址、复现命令、限制声明。

## 6. 禁止事项

- 不展示 `AGENTARTS CONNECTED`，除非当天真的有租户并完成调用。
- 不把「视频源未接入」剪掉或替换成假视频。
- 不展示真实密码、令牌、内网地址。
- 不连续展示代码超过 10 秒。
- 不用加速剪辑掩盖加载失败或报错。
- 不引用未在本次录制中实际出现的数字。

## 8. 失败备用方案

- 现场网络/租户不可用：只跑本地演示，不解说 AgentArts。
- 某个演示场景报错：切到预录片段，并在字幕标注“预录”。
- 工单未按预期生成：不要手改数据；改为展示已有历史工单的流转，并说明当前 VoI 排序结果。
- 前端加载失败：重启 `npm run dev`，重置状态后重录该镜头。

## 9. 附录：系统仿真面板（可替代 S5）

> 位置：`/` → 「现场协同管理」→「系统仿真」面板（标题旁有「合成数据 · 非真实」标签）。
> 用途：没有真实场馆实时数据时，用一条完整时间轴演示「观测进入 → 风险重算 → 独立校验 → 事件 → Agent → 人工闭环 → 复核恢复」。
> 数据边界：所有观测由后端仿真以 `source=simulation`、`provider=sim-live`、`evidence.synthetic=true` 写入，不是真实数据，不能用于精度评估。

### 9.1 操作

1. 确认已在 `/login` 登录管理员；未登录时「启动仿真」禁用并提示。
2. 点「启动仿真」。默认约 2.4 秒/步自动推进，可随时「暂停」「单步」。
3. 第 7 步会停在「需要人工操作」，面板列出下一步：
   - 在「审批中心与工单 → 待审批」批准一条现场核查工单；
   - 在「执行中」点「自动派发」，记下指派的工号；
   - 到 `/staff` 用该工号登录 → 接单 → 开始执行 → 提交反馈（人数如 4260，置信度 0.95）→ 提交并完成。
4. 回到 `/`，点仿真面板的「继续仿真」。第 8 步复核补采，第 9 步解除事件，面板与主大屏同步刷新。

### 9.2 预期状态与日志

| 步 | 阶段 | 动作 | 预期状态 | 面板应出现的关键证据 |
| --- | --- | --- | --- | --- |
| 1 | 冷启动 | 重算 | `DEGRADED` | 未生成方案；不可信区域 44 |
| 2 | 基线巡检 | 写入 44 区域基线 | `NORMAL` | `DEGRADED → NORMAL`；方案通过独立校验 |
| 3 | 客流上升 | 写入 3 区域观测 | `NORMAL` | 洞庭门 4200 人 / 置信 0.9 |
| 4 | 出口调整 | 登记并确认通道关闭 | `REROUTE` | `NORMAL → REROUTE`；事件 `corridor_closure` |
| 5 | 感知异常 | 写入低置信观测 4400 / 0.35 | `DEGRADED` | `REROUTE → DEGRADED`；发布禁止 |
| 6 | Agent 调查 | Agent 只调查并建单 | `DEGRADED` | 2 轮调查、13 次工具调用、2 个待审批工单；`Agent 不审批、不派发` |
| 7 | 等待人工 | 暂停 | `DEGRADED` | 待审批工单数；人工操作提示 |
| 8 | 复核补采 | 补采过期基线 | `DEGRADED → REROUTE` | `补采 43 个区域基线；保留 1 个`（保留现场反馈） |
| 9 | 事件解除 | 解除事件并重算 | `REROUTE → NORMAL` | `安全状态 REROUTE → NORMAL`；仿真结束 |

说明：

- 第 8 步的「补采 / 保留」数量取决于等待人工的时长：90 秒内继续，日志可能是「补采 0 个区域基线；保留 44 个」；超过 90 秒，过期但可信的区域被补采，现场反馈不会被覆盖，通常是「补采 43 个；保留 1 个」。两种都正确。
- 跳过人工反馈直接点「继续仿真」，系统会保持 `DEGRADED`，不会自动审批、派发或伪造恢复；这是刻意保留的 fail-closed 行为。
- 「停止」「重置」及「推演 A/B/C」都会终止仿真并清空仿真日志。
- 仿真结束后不再写入新观测；超过 90 秒有效期，主大屏会回到 `DEGRADED`。这是 fail-closed 的正确行为，面板底部也会给出说明；录制时在最后一步后 90 秒内收尾即可。

### 9.3 建议旁白（约 2 分钟）

> 这不是播放动画，而是后端按剧本逐步写入合成观测。冷启动没有观测，系统先降级，不假装知道现场情况。基线观测进入后恢复常态；出口关闭时重新规划；置信度掉到 0.35 时立即停止发布路线。Agent 只做调查，创建待审批工单，审批和派发必须由人完成。现场反馈写回后，系统复核：过期但可信的区域补采，人工反馈优先保留，然后状态逐步回到常态。整个过程每一步都能在右侧日志里核对。
