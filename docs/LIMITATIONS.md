# SkyGuard 局限与不适用范围

> 本文档适用于本独立仓库。场景文件位于 `data/scenarios/`，
> 默认场景为 `stadium-evacuation.json`（合成体育场散场）；`venue-default.json` 为旧版合成场馆。

> 本文档的作用是**防止系统被过度声称**。任何对外材料引用 SkyGuard 时，
> 必须同时引用本文件对应条目。

## 1. 系统性质

SkyGuard 是一个**公共安全应急疏散辅助决策原型**，用于研究与演示：

- 它**不是**经过认证的应急指挥系统，**不能**替代现场指挥员判断；
- 它**未**参与任何真实演练或真实疏散；
- 它**未**通过任何消防、公共安全或功能安全标准（如 GB 51309、NFPA 101、IEC 61508）的验证；
- 软件原型通过测试 ≠ 具备实际应急指挥资质。

用于真实场景前，必须另行完成：现场测绘与标定、可靠性测试、失效模式分析、
专业人员评审、适用的法规符合性验证。

## 2. 场景数据

`data/scenarios/stadium-evacuation.json` 是**合成的体育场散场场景**（`venue-default.json` 为旧版合成场馆）：

- 场景包含 8 个区域、12 条通道、4 个出口；面积、通道通行能力、出口接收能力均为**估算值**（`estimated`），未经现场测量；
- 有 1 条通道（`C_SERVICE`）状态与容量均为 `unknown`，用于验证"未知不得当作可用"的保守行为；
- 工作人员位置、状态、技能与无人机单位均为合成演示数据；VoI 概率与成本参数未经标定；
- 所有摄像机为 `uncalibrated`，像素到区域、像素到平方米的映射未建立；
- 示意图坐标是无量纲画布坐标，**不是**地理坐标，不可用于导航或 GIS。

## 3. 人群感知的真实状态

| 路径 | 状态 | 说明 |
| --- | --- | --- |
| `SimulationCrowdProvider` | **可用，但为模拟数据** | 人数由演示脚本显式给定，产出标记 `source: simulation`、`evidence.simulated: true`。前端与大屏以蓝色"simulation"标签区分。 |
| `RecordedVideoCrowdProvider` | **可用，本机已真实跑通** | 真实解码视频像素做运动前景连通域计数。精度有限，见 §3.1。 |
| `AscendCrowdProvider` | **未验证** | 本机无 NPU / CANN / `.om` 模型。仅实现环境探针与外部推理契约。 |

> 不得把第一条路径的结果描述为"视频推理结果"；不得把第三条路径描述为"已完成昇腾适配"。

### 3.1 CPU 视频计数方法的固有误差

`backend/python/crowd_service.py` 使用「帧差分 / MOG2 / 两者并集 + 形态学 + 连通域」：

- **过计数**：帧差会把同一目标的前后边缘检成两块（已用膨胀缓解，但仍会残留）；
- **欠计数**：人群粘连时多个目标合并为一个连通域，高密度下结果只能视为**下界**；
- **误检**：不区分人与其他运动物体（车辆、行李、飘动织物、影子）；
- **依赖固定机位**：镜头移动、光照剧变会显著降低准确度；
- **无标注验证**：本仓库没有带真值标注的人群视频，因此**没有给出准确率/MAE 指标**。
  置信度只反映"帧间检测的稳定性"，**不代表**与真实人数的接近程度。

正确做法是接入专用人群计数模型（CSRNet / Bayesian crowd counting 等），
通过 `CrowdInferenceProvider` 接口替换即可，业务层无需改动。

### 3.2 未标定摄像机一律不可信

`calibration_status` 为 `uncalibrated` 时，视频观测置信度被强制压到 ≤0.35，
低于 `min_confidence = 0.6`，系统直接进入 `DEGRADED` 并拒绝发布路线。

这是**刻意的**：像素里的前景块数量与"这个分区有多少人"之间隔着标定。
要启用视频路径，必须先在场景文件中把对应区域标为 `measured` 并提供标定版本。

### 3.3 感知回放展示包（CityStreet C3，demo_only）

`data/perception/citystreet-display/` 是对香港城市大学 VISAL **CityStreet** 数据集
C3 机位 2280–2339 帧做头部检测 + 跟踪 + 单应近似地面投影后生成的**派生显示数据**。

- **不是真实场馆测绘**：13 个区域（N/S/W/E/N-A…/Center）是该路口的**人流分区**，
  与 `data/scenarios/*.json` 的 `zones / corridors / exits / capacity` 没有映射关系；
- **配准是近似的**：东侧两处目视检查点偏差约 4.4 m 与 5.3 m；
- **时间基是推算的**：`clip_start_4hz_assumed`，按 4 Hz 从片段起点推算，非相机原始时间戳；
- **没有真值标注**：区域人数为估计值，**不得**据此报告 MAE/RMSE/F1 或"人数准确率"；
- **单机位、无跨机位去重**：遮挡与人群粘连时估计值为近似；
- **许可未确认**：原始视频与航拍底图许可均未核验；仓库只提交派生点位与区域统计，
  航拍底图不随仓库分发，由部署方本地提供并自行确认许可；
- 该数据只进入 `/api/v1/perception/*` 只读接口与前端展示，**不参与**规划、校验与四态判定。

## 4. 昇腾（Ascend）适配状态

### 4.1 已实现

- 环境探针：`CANN toolkit`、`npu-smi`、`SKYGUARD_ASCEND_CMD`、`SKYGUARD_ASCEND_MODEL` 四项检查；
- 外部推理契约：向配置的推理程序通过 stdin 发送 JSON 请求，从 stdout 读取 JSON 响应，
  并用 Zod 校验响应结构；
- 环境不满足时抛 `ProviderUnavailableError`，**绝不**返回伪造的设备名、延迟或性能数据。

### 4.2 未实现 / 未验证

- 未在真实昇腾设备上执行过任何一次推理；
- 未导出或验证任何 `.om` 模型；
- 未测量端侧推理延迟、吞吐、功耗；
- 未验证 CANN 版本、算子兼容性与模型转换链路。

### 4.3 启用条件（现场需自行完成）

1. 安装对应 CANN 版本与昇腾推理运行时；
2. 将人群计数模型转换为 `.om` 并用 `atc` 验证算子兼容性；
3. 编写一个符合如下契约的推理程序：从 stdin 读 JSON 请求
   `{region_id, camera_id, roi, video_path, model_path, max_frames}`，
   向 stdout 写 `{ok, count, confidence, model_version, device}`；
4. 设置 `SKYGUARD_ASCEND_CMD`（程序路径）与 `SKYGUARD_ASCEND_MODEL`（`.om` 路径）；
5. 调用 `GET /api/v1/safety/providers` 确认 `ascend.available === true`；
6. 完成实测并把结果写入 `TEST_REPORT.md`，再把本文档对应条目改为"已验证"。

**关于 310 系列**：不同 310 型号（310/310P/310B 等）的运行时与算子支持不同，
必须按具体型号的官方兼容性列表选择运行时与模型格式，不得假设通用。

## 5. 疏散规划模型的局限

模型是**时间扩展最小费用最大流**，不是人群动力学仿真：

- **容量是静态假设**：通道容量按人/分钟给定且不随时间变化；真实场景中会随拥堵恶化；
- **无速度衰减**：不建模人群密度导致的行进减速、瓶颈处的队形演化；
- **无恐慌与逆行**：不建模心理行为、逆行、跌倒、二次事故；
- **1 分钟离散化**：亚分钟级的通过时间向上取整，短通道的吞吐会被低估；
- **瞬时转移**：到达某区域的同一分钟即可离开，未建模换乘摩擦；
- **滞留容量近似**：区域在留容量取 `max(在留容量, 当前需求)`，避免把既有超员判为"无处可待"，
  代价是该值不再严格约束初始超员；
- **无出口前排队建模**：等待通过出口只体现为时间推迟，不体现队列长度；
- **结果是吞吐上界与分配方案**，**不是**精确疏散时间预测。

若需要时间预测，需要引入带拥堵反馈的元胞自动机或社会力模型，并做标定与验证。

## 6. 独立校验器的边界

校验器检查的是**模型内**的硬约束。它不能发现：

- 场景数据本身是错的（例如通道实际宽度与配置不符）；
- 未建模的约束（结构承重、烟气扩散、能见度、地面湿滑）；
- 观测置信度虚高（模型自评置信度不等于真实准确率）；
- 人为破坏或传感器被欺骗。

因此"通过独立校验"仅意味着"在给定输入与模型下未发现违规"，**不意味着方案在物理世界安全**。

## 7. 状态机的边界

- `NORMAL` 只表示"数据可信 + 方案通过校验"，不表示"现场安全"；
- `DEGRADED` 期间系统不产出新路线，但**不会阻断人工指挥**——人工处置通道始终保留；
- 状态由后端推导，前端不参与判定；若后端不可用，前端只显示错误，不会回退到本地推断。

## 8. 工程与部署局限

| 项目 | 现状 | 生产化需要 |
| --- | --- | --- |
| 读接口鉴权 | `/api/v1/safety/status` 等 GET 免鉴权 | 全部读接口加 JWT，并按角色限制字段 |
| 状态存储 | 进程内内存 | 外置存储（Redis/DB），否则多实例不一致、重启丢状态 |
| 审计日志 | JSONL 追加，无轮转 | 按日/大小轮转 + 归档 + 完整性校验（如哈希链） |
| 流量控制 | 无 | 限流、背压、请求超时 |
| 观测接入 | HTTP 推送 | 需要与视频网关/流媒体服务对接 |
| 并发安全 | 单进程串行假设 | 需要事务或乐观锁保证"规划期间约束不变"跨实例成立 |
| 时间基准 | 使用系统时钟 | 需要 NTP 同步与时钟漂移监控 |

## 9. 明确禁止的表述

以下说法**不成立**，不得出现在任何材料中：

- "已完成昇腾边云协同部署" / "已验证昇腾推理性能"；
- "该系统可用于真实场馆疏散指挥"；
- "已获得公共安全认证" / "符合消防规范"；
- "人群计数准确率 XX%"（无标注数据集，无准确率可言）；
- "平均疏散时间 X 分 Y 秒"（模型不预测时间，只给吞吐分配）；
- "大模型自动生成安全路线"（大模型只做 NLP 录入，不参与安全判定）。

## 10. V7.0 预测、动态规划与联合 VoI 的边界（2026-11-09）

### 10.1 预测

- `ensemble_v70`（Kalman / ARIMA / Holt-Winters / 在线 LSTM / 状态感知集成）是研究级实现，
  **未在真实场馆时序上标定**；
- 实验显示集成在多数机制上优于 persistence，但**不是任何单一机制的最佳方法**；
  突增（surge）场景 95% 区间经验覆盖率明显低于名义值，**不得用于安全告警阈值**；
- Regime 检测在短窗口上不稳定（periodic/surge/noisy 准确率有限），只能作为候选筛选提示；
- 在线 LSTM 为轻量基线（隐藏单元 4、截断 BPTT），训练数据很少，负结果已保留；
- 预测失败或区间过宽时，VoI 预测动作被阻断；安全四态仍由观测可信度决定。

### 10.2 动态规划与拥堵

- MPC、时间扩展最大流、受限 MILP 与动态队列执行模型均为**研究原型**；
- BPR 行程时间放大（a=0.15, b=2）、出口拥挤服务衰减（factor = 1/(1+q/(μ·5))，下限 0.5）
  是**未标定启发式**，不是实测人群速度或服务率模型；
- 执行模型不建模逆行、恐慌、跌倒、二次事故与出口外空间；
- 实验在**合成场景 + 合成入流**下进行；静态计划未响应入流是策略设定，不是执行模型缺陷；
- 预测与队列反馈相对“仅滚动重规划”未显示显著增量收益；该结论只适用于即时响应假设，
  不能外推为“预测无用”，也不能证明真实场景中的收益；
- 受限 MILP 只对竞争最激烈的 ≤5 个区域枚举二进制出口选择，不是全局 MILP 求解器。

### 10.3 联合 VoI

- 相关性（0.5）与冗余折扣（0.6）来自场景文件，是**未标定的合成先验**；
- 联合 VoI 是启发式近似，不是联合 POMDP 精确解；
- 公平实验中总风险降低略低于现有多区域 VoI，最坏区域风险略低，效应量很小；
  **不得宣称联合 VoI 全面更优**；
- Oracle 知道真实状态，只作为检测覆盖上界，不代表可实现的策略。

### 10.4 禁止的 V7 表述

- “预测精度达到 XX%”或“区间已校准可用于安全告警”；
- “MPC 已在真实场馆验证”或“动态规划证明可缩短真实疏散时间”；
- “联合 VoI 优于现有多区域 VoI”（当前证据为混合/略低）；
- “已完成昇腾/AgentArts 实机验证”；
- “拥堵模型已标定”或“BPR/服务衰减参数来自实测”。

## 11. V7.1 滚动重规划、预测区间与 Shadow Mode 的边界（2026-11-09）

### 11.1 滚动重规划

- 所有实验为合成场景/入流；BPR、出口服务衰减、事件阈值均为未标定启发式；
- V7 MPC 完成时间更短但路线切换人数约为 legacy 的 5.8 倍；切换成本未系统优化；
- 事件触发对 legacy 有效、对 V7 有害；不得默认开启；
- 预测/队列反馈没有显著增量；该结论受“即时响应、无调度延迟/预留提前期”假设限制；
- 不得把合成完成时间表述为真实疏散时间。

### 11.2 预测区间

- ACI+变点检测改善 surge/regime_shift 尾部覆盖，但整体覆盖无显著提升，periodic 覆盖下降、宽度与门控失败率上升；
- 区间不是正式统计置信区间；即使覆盖改善，也不得直接用于安全告警阈值；
- 可靠性门控失败时预测不得进入 VoI/规划；安全四态仍由观测可信度决定；
- 预测点估计仍是 V7.0 集成，未重新训练。

### 11.3 Shadow Mode

- 默认关闭；当前只比较单步时间扩展方案，不比较 MPC 执行策略；
- 超时是事后预算检查，不是抢占式中断；记录仅内存，重启丢失；
- 未做多实例、真实场馆或 AgentArts/昇腾实机验证；
- `v7_eligible_for_review` 不是安全批准，V7 方案从未发布；
- 启用前必须满足 `docs/V7_SHADOW_MODE.md` 验收清单。

### 11.4 公开数据集

- MOT20、Stanford Drone、NWPU-Crowd 许可已核验；UCF-QNRF 无明确许可；ShanghaiTech 数据许可未明确；
  JHU/ETH/UCY/CityStreet 本轮未核验；
- **没有公开数据集提供 SkyGuard 的区域-通道-出口疏散决策标签**；
- 静态图片计数精度不得表述为动态疏散预测精度；轨迹数据只能做跨域代理研究；
- 不随仓库分发原始数据。

### 11.5 禁止的 V7.1 表述

- “滚动重规划已在真实场馆验证”；
- “预测/队列反馈显著提升疏散效果”；
- “ACI 使预测区间全面校准”；
- “Shadow Mode 已启用/已通过安全验收”；
- “路线稳定已降低切换成本”；
- “事件触发全面优于周期重规划”；
- “已完成 AgentArts/昇腾/无人机实机验证”。

## 12. V7.2 路线稳定性、标定与可信集成的边界（2026-11-10）

### 12.1 稳定性机制

- 迟滞/切换惩罚/承诺/自适应均在**合成场景**中评估；参数（0.05、10/人、6 分钟、80% 份额）未标定；
- 稳定性降低切换的代价是完成时间、队列与最大密度上升；不得只引用切换下降；
- 惩罚与承诺在当前参数下结果几乎相同，不能宣称两者独立优于对方；
- 自适应在本实验退化为承诺，未体现混合优势（负结果）；
- 高需求/容量紧张时承诺候选会被安全护栏拒绝，收益不稳定。

### 12.2 承诺式求解与容量

- 逐区域顺序求解是贪心多商品近似，不是联合最优；
- 双向通道共享容量采用迭代比例分配，最多 8 轮；不保证全局最优，但最终逐分钟容量复核；
- 容量冲突时份额 0.8→0.6→0.4→0.2 回退；仍冲突则调用方必须拒绝；
- 不得把「容量复核通过」表述为真实人群动力学安全。

### 12.3 场馆标定

- 当前只有合成档案与合成样本；没有真实测绘、摄像机标定、授权数据；
- 标定流水线能表达真实参数，但不等于已完成真实标定；
- `estimated/uncalibrated` 不得用于真实疏散指挥；
- 合成数据即使统计稳定也被降级为 `estimated`。

### 12.4 Shadow

- 回放是适配器层，不覆盖真实 HTTP 并发、进程崩溃、持久化中断；
- 超时是事后检查，不是抢占；记录仅内存；
- 默认关闭、未启用、不是安全批准；
- 240 次回放只覆盖合成场景与注入模式，不代表运营验证。

### 12.5 华为生态

- AgentArts：无真实租户/凭证；本地 stub 只验证适配器契约；
- Ascend：无 `npu-smi`/`atc`/CANN；ONNX 基准为 CPUExecutionProvider；
- 参考模型不是生产预测器；CPU 延迟不能替代 NPU 性能；
- 不得把 `executed_cpu_only` 表述为昇腾实机结果。

### 12.6 禁止表述

- 「稳定性机制全面优于标准 MPC」；

## 13. V7.3 自适应稳定性、导入与部署的边界（2026-11-10）

### 13.1 自适应稳定性

- 自适应惩罚/振荡惩罚/风险权重/多目标权重均为未标定启发式；
- 切换/振荡下降伴随完成时间、队列、最大密度上升；不得只引用有利指标；
- 动态容量场景下收益缩小；不能宣称普遍有效；
- 安全违规指标是容量冲突 + 未疏散标记的代理，不是完整 Validator 结论。

### 13.2 导入与标定

- 只有合成档案与 CSV 测试夹具；没有真实场馆、摄像机或授权数据；
- 公开/授权适配器只验证契约，不代表真实数据集/授权；
- 视频接口输入是已计数帧，不做 CV，不代表计数精度；
- 冲突检测阈值（不同 provider、差异 50%、窗口 300s）是启发式。

### 13.3 Shadow

- 适配器层回放，不覆盖真实 HTTP 并发、持久化中断、平台重试；
- 过期快照/冲突观测已 fail-closed，但仍不是运营验证；
- Shadow 默认关闭、未启用、不是安全批准。

### 13.4 AgentArts / Ascend

- AgentArts 无真实租户/Trace；本地 stub 不等于实机；
- 无 npu-smi/atc/CANN/OM；ONNX CPU 基准不是 NPU 性能；
- OM 元数据模板明确未执行，不得用于实机声明。

### 13.5 禁止表述

- 「自适应稳定性全面优于标准 MPC」；
- 「动态容量下仍保持全部收益」；
- 「已完成真实场馆标定」；
- 「已接入 AgentArts」；
- 「已在昇腾 NPU 运行」；
- 「Shadow 已验证真实运营」。

## 14. V7.4 门控、检测与生产检查的边界（2026-11-10）

### 14.1 执行感知门控与 Pareto

- 门控比较的是「保留承诺的候选」与「标准重规划」，不是全局稳定性控制器；
- 零容差门控会拒绝全部候选，系统回退标准 MPC；**不存在本模型下的零代价稳定性**；
- 1min/2000 人·分钟容差是预先设定，不是标定值；换场景需重新评估；
- Pareto 候选必须严格降低切换才被采用；若门控拒绝，收益为 0 而非负值；
- 候选求解是贪心近似，逐分钟容量复核通过不等于真实人群动力学安全；
- 平均每次规划约 18.45 个候选、p50 40.9ms；未做规划吞吐压测。

### 14.2 风险敏感惩罚与区域选择性承诺

- riskDiscount 在自适应模式下几乎不影响决策（承诺/拥堵分支绕过惩罚比较）；
  D 与 C 逐样本相同，必须作为负结果报告；
- 区域选择性承诺已实现但未进入 A-F 评测矩阵，只能写「已实现、未公平评测」；
- 不得通过调整阈值制造「风险敏感有效」的正结果。

### 14.3 Surge/regime 检测

- CUSUM/3σ 均在合成序列上评测；稳定段种子误报率约 33%；
- noisy 机制两者检测率 0，说明高噪声下阈值法失效；
- 中位延迟 5/7 步；检测率提升不等于可提前预警真实事故；
- 不得将检测指标表述为真实事件预警能力。

### 14.4 标定质量

- 时钟偏移、缺失、可靠性均为夹具/代理：可靠性 = 可用性×置信度×稳定性，不是准确率；
- 动态容量计划是合成演练值，未用真实容量数据标定；
- 覆盖率 0.125 只反映夹具中 1/8 区域有观测，不代表部署覆盖率；
- 同步/拒绝逻辑已验证，但未在真实多摄像机网络运行。

### 14.5 生产检查

- Docker daemon 不可用 → 镜像/容器部署 **未验证**，不得声称可部署；
- 负载为本地状态端点（100 次/并发 10），不代表规划吞吐或真实并发；
- 浏览器 E2E 只覆盖登录→指挥中心→代理 API，不覆盖写操作、权限拒绝、异常恢复；
- CI 仅做 YAML 解析，实际流水线未在 GitHub Actions 运行。

### 14.6 禁止表述

- 「零代价降低切换」；
- 「风险敏感惩罚优于自适应」；
- 「区域选择性承诺已验证有效」；
- 「CUSUM 可在真实场景提前预警」；
- 「可靠性分数是准确率」；

## 15. V7.5 研究模块的额外边界（2026-11-10）

### 15.1 低误报检测

- 全部为合成多传感器序列；传感器噪声/可靠性/缺失/延迟/偏置是注入参数；
- 零误报只在给定机制与参数下成立；真实视频/无人机数据未测试；
- 代价是 1–2 步延迟；延迟与误报的取舍依赖场景，未做代价标定；
- 检测器只输出警告/审计，不发布方案、不替代四态。

### 15.2 承诺与状态机

- 区域选择性承诺在本轮为负结果（切换高于全局承诺/自适应），不得说成有效；
- 容量感知承诺在 headroom 0.9 下未显著降低切换并引入未疏散，属于未达成目标的实现；
- 紧急状态机的 0 响应是控制步内测量，不是实时系统时延；
- 状态机不替代人工审批、独立 Validator 或四态判定；事件注入不等于真实事故。

### 15.3 多目标

- Pareto 前沿与膝点来自同一实例的候选集合，是离线分析上界；
- 部署时必须单次规划并通过独立校验，不能把离线选择结果当作在线性能；
- 权重配置是预先声明的研究参数，不是场馆标定值。

### 15.4 多传感器融合

- 融合输入为合成读数；`reliability`/`confidence` 是代理，不是准确率；
- 冲突/时钟偏移 fail-closed 已验证，但可用率只有 0.7497，部署必须接入降级链路；
- 持续偏置不是冲突，可靠性加权无法消除；不得宣称融合解决标定问题；
- 点估计误差与 reliability_weighted 同级，不得宣称融合降低 MAE。

### 15.5 平台与证据

- AgentArts 仅本地 stub，真实平台 `not_configured`；
- 昇腾无 `npu-smi`/`atc`/CANN，ONNX 仅 CPUExecutionProvider，OM 未执行；
- Docker daemon 不可用，镜像/容器未验证；
- CI 中的 V7.5 步骤只运行 detection+fusion 冒烟，不等于完整 30 种子实验；
- 浏览器 E2E 只覆盖登录→指挥中心→代理 API。

- 「V7.5 检测可在真实场馆提前预警」；
- 「区域选择性/容量感知承诺已被证明有效」；
- 「融合降低了传感器误差」或「融合解决了偏置」；
